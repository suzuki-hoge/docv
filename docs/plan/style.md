# HTML のデザイン調整

`docv build` が作る HTML を、Web デザインと CSS の観点で見直した課題と、その対応方針。すべて片付いたら、このファイルは消す。

## 前提

- HTML は、AI Agent が書き足していくドキュメントの全体像を、人間が素早く掴むための画面。じっくり読ませるドキュメントサイトでも、外向けの製品サイトでもない
- 複数のプロジェクトで同じ型を使い、どのプロジェクトでも同じ場所に同じものがあること自体に価値がある
- 読み手は、clone したリポジトリを手元のブラウザで開く開発者。GitHub で辿る JPG も、HTML と同じ重みの出力
- 重く見ること: 一目で掴めるか、現在地が分かるか、見出しの階層、プロジェクトをまたいだ一貫性、JPG での読みやすさ、デスクトップの狭いウィンドウ（エディタと並べたとき）
- 軽く見ること: ブランドの表現、装飾、アニメーション、スマホ

## 課題

### 重要度: 高

- [x] 1. h2 と h3 が同じ見た目。どちらも 1.25em で、同じ細い罫線が付く。章と節の区別がつかず、目次では入れ子なのに本文では並列に見える
- [x] 2. 幅が 760px 以下になると、ナビが壊れる
  - ナビは横並びで折り返さないので、和文のラベルが 1 文字ずつ縦に折れ、後ろの項目が画面の外に出る
  - 表に横スクロールの逃げ道がなく、ページごと横にはみ出す（現在の設定の textlint の表）
  - 左右の余白 40px が、狭い幅では大きすぎる
- [x] 3. ADR 一覧で、つながりのない決定も 1 行に 1 枚ずつ並ぶ。ページが縦に長くなり、右の 3/4 が空く。決定が増えるほど悪化する
- [x] 4. 現在地と状態が見えない
  - ページを見て編集したくなったときに、元のファイルがどれか分からない
  - ADR の個別ページに、打ち消された決定かどうかが出ない
  - プロジェクト概要、ADR、プロジェクト詳細、現在の設定のページに h1 がなく、本文からどのページか分からない

### 重要度: 中

- [x] 5. リンクを色だけで示している。本文の文字色とのコントラスト比は 2.99:1 で、色だけで示すときに WCAG が求める 3:1 に届かない。本文のリンクは、マウスを乗せても変わらない
- [x] 6. コードブロックの文字が、本文中のインラインコードより小さい。`code, pre { font-size: 0.9em }` が `<pre><code>` で 2 回かかり、0.81em になる
- [x] 7. キーボードのフォーカスが見えない。検索欄は `outline: none`、OS のタブはラジオボタンを透明にしている
- [x] 8. 罫線が二重になる。ブラウザ既定の `<hr>` の直後に、h2 の下線が来る
- [x] 9. 意味を持つグレーが薄い。背景とのコントラスト比は、未作成のカードの文字が 2.85:1、選ばれていない候補が 3.0:1。「未作成」が色でしか伝わらない

### 重要度: 低

- [x] 10. 色がすべて直書きで、CSS 変数がない。色の調整がしにくい
- [x] 11. 幅 1920px では、目次が本文から離れて右端に寄る。本文の 1 行も約 60 字あり、和文としては長め
- [x] 12. 和文が語の途中で折り返される（Doc ガイドの表の「サービス / 説明」）
- [x] 13. 図を出力先の外から相対パスで読むのに、ビジュアライズのページは「そのままホスティングしても見られる」と書いていて、食い違う。出力先だけを公開すると図が表示されない

## 対応方針

「飾らない」はそのままにして、階層と状態を見えるようにし、狭い幅やキーボード操作でも壊れないようにし、値を変数にまとめる。変えないのは、飾らないトーン、カードの固定幅と固定順、JS に頼らない作り、印刷の表示（JPG）。

### CSS だけで直すこと

- 1: 段差をつける。h1 は 2em、h2 は 1.4em で細い罫線、h3 は 1.15em で罫線なし、h4 は 1em。h2.group も普通の h2 と同じ見た目にする
- 2: 760px 以下では、ナビの項目を折り返して並べ、項目の中では折り返さない。main の左右の余白を 16px にする
- 5: 本文（段落、箇条書き、表のセル）の中のリンクに、薄い下線を付ける。マウスを乗せると下線を濃くする。ナビ、カード、目次、タブは下線なしのまま
- 6: `pre code` の文字の大きさを `1em` にして、2 回かからないようにする
- 7: `:focus-visible` で、フォーカスのある要素に 2px の枠を出す。OS のタブは、透明のラジオボタンの代わりにラベルに枠を出す。検索欄の `outline: none` をやめる
- 8: `<hr>` を 1px の細い線にし、直後に h2 が来る `<hr>` は出さない
- 9: 選ばれていない候補と未作成のカードの文字を、補足と同じ濃さ（4.5:1 以上）にする
- 10: 本文、補足、罫線、背景、強調の色を CSS 変数にまとめる。タグの 8 色のように 1 か所でしか使わない色は、その規則に残す
- 11: 本文と目次をひとまとまりにして中央に寄せ、目次を本文の隣に置く。段落と箇条書きの 1 行は 46em までにし、表、コード、カードは全幅のままにする
- 12: 見出し、表、カード、ADR の箱、目次、ナビに `word-break: auto-phrase` を付け、文節で折り返す。見出しは `text-wrap: balance`、段落と箇条書きは `text-wrap: pretty` にする。どちらも Chrome 系で効き、ほかのブラウザでは無視されるだけ。JPG は Chrome で撮るので効く

### HTML の構造を変えること（ビジュアライズのページを先に直す）

- 2: 表をすべて `<div class="table-scroll">`（`overflow-x: auto`）で包み、はみ出しても表の中だけで横にスクロールさせる。印刷の表示では包みを効かせない
- 3: ADR 一覧では、つながりのある決定だけをレーンにし、単独の決定はまとまりごとに箱を折り返して並べる。並びは、どちらも今と同じ日付と id の順
- 4: 現在地と状態を出す
  - Slot、ADR、Free ファイルのページの h1 の上に、元のファイルのルートからのパスを小さく出し、横にコピーのボタンを置く。ボタンは JS が動くときだけ出し、JPG には写さない（パスは写す）。JS は検索の JS と同じく `assets/` に置く
  - 打ち消された ADR のページでは、h1 の下に、打ち消されたことと新しい決定へのリンクを出す。下の前後のカードには「← 過去の決定」「新しい決定 →」の見出しを付け、カーソルキーで移れることを書く
  - ADR 一覧の h1 の下に、破線の箱が打ち消された決定であることを書く（打ち消された決定があるときだけ）
  - プロジェクト概要、ADR、プロジェクト詳細、現在の設定のページに、ページの名前の h1 を置く。現在の設定の最初の h2 は、h1 と重ならないよう「docv.yaml」にする
- 9: 未作成のカードを破線の枠にし、枠の上に「未作成」の文字を出す

### ドキュメントだけを直すこと

- 13: 画像は出力先にコピーしない。出力先をコミットするリポジトリでは画像が 2 か所に入り、決定（ADR の「HTML のリンクはページにだけ張る」）でも画像は元のファイルを読む例外にしている。ビジュアライズのページの記述を、ホスティングするときは画像を置いたディレクトリも含めて公開する、と直す

### 見送ること

- パンくず: どのトップのページの下にいるかは、左のサイドバーの強調で分かる。階層はトップのページと個別のページの 2 段で、間の「まとまり」はページではなく見出しなので、パンくずの項目がどれも同じページを指すことになる
- ダークモード: Slot や Free ファイルに載せる図（SVG）は白い背景を前提に描かれることが多く、暗い背景では線が見えなくなる。コードブロックの色も明るい背景向けの配色で HTML に埋め込んでいる。JPG は明るい配色で揃えたいので、ブラウザの設定で配色が変わるのも避けたい
