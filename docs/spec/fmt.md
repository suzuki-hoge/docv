# fmt

管理対象のファイルの空行、表の余白、リストの記号などを、毎回同じ形に整形するコマンド。エディタごとの自動整形の違いで差分が出るのを防ぐ。check や new との連動は docv.yaml の format.enabled で決める（[spec/config.md](config.md)）。

---

## 1. 使い方

```sh
docv fmt               # 管理対象のファイルをすべて整形する
docv fmt <パス...>     # 指定したファイルだけ整形する
docv fmt --check       # 書き換えず、整形が必要なファイルを出す。あれば終了コード 1
```

- 対象は管理対象のファイルだけ。docs の項目で check: off にしたファイルは整形しない
- Markdown として読めないファイルは、書き換えずにエラーとして出す

---

## 2. 整形の仕方

- dprint-plugin-markdown を Rust のライブラリとしてバイナリに埋め込んで使う。Prettier を使わないのは、Node.js がいらず、docv の版で整形の結果が固定されるため
- 整形の形は docv が決め、設定では変えない。好みで揉めないことと、どのプロジェクトでも同じ形になることを優先する

| 対象 | 整形の形 |
|---|---|
| 文の折り返し | 変えない。改行の位置はそのまま残す |
| 空行 | ブロック（段落、見出し、リスト、表、コードブロック）の間を 1 行にする |
| 表 | 列の幅をそろえる。全角文字は 2 文字分として数える |
| 箇条書きの記号 | `-` |
| 強調の記号 | 斜体は `*`、太字は `**` |
| 見出し | `#` の形 |
| コードブロック | 中身は変えない |
| 行末 | 末尾の空白を消す。改行は LF にし、ファイルの最後に改行を 1 つ置く |
| frontmatter | 中身は変えない |

整形したファイルをもう一度整形しても、結果は変わらない。

---

## 3. ほかのコマンドとの関係

format.enabled が true のときは、次のように連動する。

| コマンド | 動き |
|---|---|
| `docv check` | 整形が必要なファイルを、ルール ID format-diff の error として出す |
| `docv new`、`docv retire` | 整形してから書く |

format.enabled が false でも、`docv fmt` を直接実行すれば整形できる。

---

## 4. エディタの自動整形

- エディタの Markdown の自動整形は切り、保存のときに `docv fmt <ファイル>` を外部の整形ツールとして実行するように設定する
- AI Agent には、ファイルを編集するたびに hook で `docv fmt <ファイル>` と `docv check <ファイル>` を実行させるとよい。hook は利用者が設定する
