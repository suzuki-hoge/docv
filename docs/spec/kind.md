# 種類

docv が組み込みで持つドキュメントの種類と、種類ごとに書く内容・粒度・見出しの制約。種類とファイルの対応は [spec/config.md](config.md)、書き方全体のルールは [spec/writing.md](writing.md)。

---

## 1. 一覧

| 種類      | 時間 | 答える問い                         | 粒度                                                                                               | 見出しの制約        |
| --------- | ---- | ---------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------- |
| overview  | 現在 | これは何で、どこから見ればいいか   | プロジェクトに 1 つ                                                                                | なし                |
| spec      | 現在 | 〜はどう振る舞うか、どうあるべきか | 話題ごとに 1 ファイル                                                                              | なし                |
| operation | 現在 | どう実行するか                     | 契機（初回のセットアップ、日々の運用、開発、リリースなど）ごとに 1 ファイル。1 つの章に 1 つの作業 | なし                |
| cost      | 現在 | 何にいくらかかるか                 | 課金先ごとに 1 ファイル、または全体で 1 ファイル                                                   | 単価、見積もり      |
| rule      | 現在 | どう書くか、何を守るか             | 対象（コード、ドキュメント、レビューなど）ごとに 1 ファイル                                        | なし                |
| plan      | 未来 | 何をやるか                         | 契機と担当ごとに 1 ファイル                                                                        | なし                |
| proposal  | 未来 | 何をどう変えることを検討しているか | 1 つの案ごとに 1 ファイル                                                                          | 案、決めること      |
| fixme     | 未来 | 何が決まっていないか、何を調べるか | 話題ごとに 1 ファイル。1 つの章に 1 つの項目                                                       | なし                |
| archive   | 過去 | 何を外し、なぜ外したか             | 移した元のファイルごとに 1 ファイル                                                                | 章は「日付 見出し」 |
| tmp       | なし | 後で見るかもしれないものは何か     | 自由                                                                                               | なし                |

- 見出しの制約は、その語を含む章（h2）があることを check が確かめる（[spec/check.md](check.md)）
- spec、operation、rule は、話題によって章の構成がまったく違うので、見出しを固定しない。範囲は答える問いで守る
- テンプレは [templates/](../../templates) にある。`docv new` はこれを使ってファイルを作る。docv.yaml でプロジェクト独自のテンプレに差し替えられる

## 2. 現在の種類

### overview

- プロジェクトの目的、構成、どこから見ればいいかを書く
- README.md を overview にしてよい。README.md には frontmatter を書かず（GitHub が表として表示するため）、question は docv.yaml に書く

### spec

- 振る舞い、データの意味、境界、今の状態の理由（1〜2 行）を書く
- コードを読めば分かること（関数名、型、カラムなど）は書かない
- 検討中の変更は書かない。proposal にする

### operation

- コマンド、手順、うまくいかないときの対処を書く
- 1 つの章を 1 つの作業にする

### cost

- 単価（いつ時点の値か）、見積もり、費用を理由に決めていることを書く
- 料金は cost にだけ書き、ほかの種類からはリンクする

### rule

- 書き方や守ることを書く
- 人間が書き、AI Agent は読む

## 3. 未来の種類

### plan

- やると決めたタスクを、チェックボックス（`- [ ]`）で書く
- frontmatter の status に todo / doing を書く
- 終わったタスクは消す。チェックを付けて残さない。タスクがすべて終わったら、ファイルごと消す
- 終わったことは PR に残るので、plan は archive に移さない

### proposal

- 背景、案、決めることを書く
- 採用したら、現在のドキュメントを書き換え、proposal は理由を「採用」として retire する
- 却下したら、却下した理由を付けて retire する

### fixme

- 決まっていないこと、調べることを書く。1 つの章に 1 つの項目を書き、見出しは問いの形にする
- 案があって検討している段階になったら、proposal にする
- 決まったら、答えを現在のドキュメントに書き、項目を消す。比べた選択肢を残したいときは retire する

---

## 4. 過去の種類

### archive

- 現在と未来のドキュメントから外した内容と、外した理由を書く。`docv retire` が書く
- 移した元のファイルごとに 1 ファイル。新しいものを上に置く
- 過去の言い回し（`〜に変更した`、`以前は` など）を書いてよいのは archive だけ

---

## 5. 時間を持たない種類

### tmp

- AI Agent と作業すると、意思決定が速く次々に起き、頭では管理しきれない。一方で、GitHub Issue に書くほどまとまってもいない。そういうものを、後で見るために置いておく
- 書き方のルールはない。frontmatter も question もいらない
- check（書式の規則と textlint を含む）と fix の対象にしない。HTML にも `docv index` にも出さない
- いつ消えてもよい。そのため、ほかのドキュメントからリンクも言及もしない。tmp の外から tmp へのリンクは、check が error にする（[spec/check.md](check.md) の link-to-tmp）
- 残す価値が出てきたら、内容に合う種類のドキュメント（fixme、proposal など）か Issue に書き直す
- 推奨する配置では docs/tmp/ に置く（[spec/config.md](config.md) の 5 章）
- コミットするかどうかはプロジェクトが決める。.gitignore に入れても、docv は tmp のファイルを読まないので困らない

---

## 6. 独自の種類

- docv.yaml の kinds で足せる。決めるのは、ID、表示名、時間（future / present / past）
- 時間を決めると、同じ時間の組み込みの種類と同じ扱いを受ける。present なら過去の言い回しが警告され、past なら index に載らない
- 見出しの制約は持たない。テンプレは docv.yaml の templates で指定できる
