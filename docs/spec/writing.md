# 書き方

docv で管理するドキュメントを書く・直すときのルール。人間も AI Agent も従う。`docv desc` が出すルールファイルは、この内容を AI Agent 向けにまとめたもの。考え方は [spec/concept.md](concept.md)。

---

## 1. 書く前に決めること

1. 書くべき変更か
   - 仕様、手順、費用、規約、計画、検討、未決のどれかが変わったときだけ書く
   - コードを変えただけなら書かない。「書かない」も正しい結論として扱う
2. どの種類か（[spec/kind.md](kind.md)）
3. どのファイルか
   - `docv index` で各ファイルの問いを見て、問いに収まるファイルを選ぶ
   - 収まるファイルがなければ、`docv new` で作る

---

## 2. 何をどこに書くか

| 書く内容 | 書く場所 |
|---|---|
| やったこと | PR とコミットメッセージ。ドキュメントには書かない |
| 決まったこと | 現在のドキュメント。前の内容を直接書き換える |
| 今の状態の理由 | 現在のドキュメントに 1〜2 行 |
| 捨てた案、前の状態、議論の経緯 | archive（`docv retire` で移す） |
| 検討中の変更 | proposal |
| 決まっていないこと | fixme |
| 実装状態、コードの改善点 | 書かない。必要なら Issue にする |
| まとまっていない意思決定、後で見るかもしれないメモ | tmp。ほかのドキュメントからリンクも言及もしない |

---

## 3. 書き換える

- 現在のドキュメントは、前の内容を直接書き換える。後ろに足していかない
- 古い内容は、残す価値があるとき（なぜ変えたか、何と比べて捨てたか）だけ `docv retire` で archive に移す。それ以外は消す
- `〜に変更した`、`以前は`、`未実装` のような言い回しは、現在のドキュメントに書かない。check が警告する（[spec/check.md](check.md)）

---

## 4. 範囲を守る

- 問いに収まらない内容を足さない
- 内容を収めるために、問いを広げない
- 問いに対してファイルが大きくなったら、問いを分け、ファイルも分ける

---

## 5. 読み書きの権限

| 対象 | 人間 | AI Agent |
|---|---|---|
| 現在と未来のドキュメント | 読む、書く | 読む、書く |
| rule | 読む、書く | 読む |
| archive | 必要なときに読む | 経緯を聞かれたときだけ読む。書くときは `docv retire` を使う |
| docv build の出力 | 見る | 読まない、書かない |
| tmp | 自由 | 自由。ほかのドキュメントからリンクも言及もしない |
| 管理外のファイル | 自由 | 自由 |

---

## 6. 書式

- docv が決めるのは、frontmatter（[spec/frontmatter.md](frontmatter.md)）と、種類ごとの見出しの制約だけ
- 章番号、文体、強調の使い方などは、プロジェクトが決めて rule に書く
- そのうち機械で確かめられるものは、docv.yaml で書式の規則（[spec/style.md](style.md)）と textlint（[spec/textlint.md](textlint.md)）を使うように設定して、check で確かめる
- 空行や表の余白は、手で揃えずに `docv fmt` で整形する（[spec/fmt.md](fmt.md)）
