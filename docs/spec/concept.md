# docv の考え方

docv が何を解決し、どんな原則でルールと CLI を決めているか。種類は [spec/kind.md](kind.md)、書き方は [spec/writing.md](writing.md)、CLI は [spec/cli.md](cli.md)。

---

## 1. 解決すること

- ドキュメントが無秩序に書き足され、全体像がつかめない
- 久しぶりに触った自分やほかのメンバーが、「どう実行するの？」「何にいくらかかるの？」「〜の仕様は？」にすぐ答えられない
- そのたびに AI Agent に全部読ませてまとめさせると、時間とトークンがかかり、結果も毎回変わる

docv は、ドキュメントのルールと、そのルールを前提にした CLI を 1 つのフレームワークとして提供する。docv を使うと決めれば、個別のプロジェクトでドキュメントの管理方法を考えずに済む。

---

## 2. 同じデータソースへの 2 つのアクセス方法

```
詳細ドキュメント（Markdown + frontmatter）  ← 唯一のデータソース
   ├─ AI Agent: docv index でファイルの一覧と問いを知り、必要なファイルだけ読む
   └─ 人間: docv build が生成する HTML（任意で JPG）を見る
```

| 読む人 | 読むもの | 入口 |
|---|---|---|
| AI Agent | Markdown | `docv desc`（ルール）、`docv index`（ファイルの一覧） |
| 人間 | HTML、JPG | `docv build` の出力 |

- 詳細なドキュメントは、AI Agent が読むものであり、HTML のデータソースでもある。人間が Markdown を直接読むことは前提にしない
- 理解するためのコストは、書くときに少しずつ払う。AI Agent は書くたびに frontmatter を付け、インデックスと HTML は CLI が LLM を使わずに作る
- 同じ入力からは、毎回同じ出力ができる

---

## 3. 時間で分ける

| 時間 | 種類 | 人間が読む頻度 |
|---|---|---|
| 未来 | plan、proposal、fixme | ときどき |
| 現在 | overview、spec、operation、cost、rule | よく読む |
| 過去 | archive | ほとんど読まない |

```
未来 ──(決まる)──▶ 現在 ──(置き換わる・廃止される)──▶ 過去
  └──────────────(却下される)──────────────────────▶ 過去
```

- 人間が知りたいのは、ほとんどの場合現在の状態であり、経緯を知りたいことはまれ。現在のドキュメントには最新の状態だけを書く
- やったことはドキュメントに書かず、PR とコミットメッセージに書く。ドキュメントが書き足され続けるのは、やったことを書き足すため
- 状態が変わったら現在のドキュメントを書き換え、残す価値のある古い内容だけを過去のドキュメントへ移す（[spec/retire.md](retire.md)）
- 時間の外に、まとまっていない意思決定やメモを後で見るために置いておく tmp がある。tmp は管理も検査もせず、HTML にも出さない（[spec/kind.md](kind.md) の 5 章）

---

## 4. 実装状態を書かない

- 仕様は、実装されているかどうかにかかわらず「こうあるもの」として書く。ドキュメントは実装を写すものではなく、仕様の正本である
- 検討中の仕様は proposal として書く。コードの改善は Issue にする
- docv は、ドキュメントと実装のずれを検出しない

---

## 5. 責任範囲を守る

- ファイルごとに、答える問いを 1 文で宣言する（[spec/frontmatter.md](frontmatter.md) の question）
- 問いに収まらない内容は、別のファイルに書くか、新しいファイルを作る
- 大きさは文字数ではなく、問いと種類ごとの粒度で決める。人間は長いファイルを読まない

---

## 6. 管理するファイルを選べる

- docv が管理するのは、docv.yaml で種類を指定したファイルだけ
- それ以外のファイルは、管理外として自由に置ける。check の対象にならず、HTML では「その他」に並ぶ
- 既存のプロジェクトには、全部を管理外にした状態から、ディレクトリ単位で少しずつ管理対象に入れていける（[spec/migrate-guide.md](migrate-guide.md)）

---

## 7. docv がしないこと

| しないこと | 代わりに |
|---|---|
| AI Agent 向けの Skill や plugin の提供 | ルールファイルを公開し、`docv desc` で出す。ルールに従って直させる作業は、利用者が AI Agent に頼む |
| CLAUDE.md や hook の設定 | 入れたい利用者が自分で書く |
| CI での実行 | すべてローカルで実行する |
| 実装とのずれの検出 | 実装状態を書かない |
| 変更履歴を書くこと | 変更は git と PR に残す。捨てたものとその理由は archive に残る |
