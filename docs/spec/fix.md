# fix

管理対象のファイルを、毎回同じ形に整形し、textlint で直せるところを直すコマンド。エディタごとの自動整形の違いで差分が出るのを防ぐ。check や new との連動は docv.yaml の format.enabled で決める（[spec/config.md](config.md)）。textlint のルールは [spec/textlint.md](textlint.md)。

---

## 1. 使い方

```sh
docv fix                 # 管理対象のファイルをすべて直す
docv fix <パス...>       # 指定したファイルだけ直す
docv fix --no-textlint   # textlint の自動修正を飛ばし、整形だけをする
```

- 対象は管理対象のファイルだけ。docs の項目で check: off にしたファイルと、tmp のファイルは直さない
- 書き換えたファイルを出す
- Markdown として読めないファイルは、書き換えずにエラーとして出し、終了コード 1 で終わる
- 直すのは fix だけで、check は確かめるだけ。check が通らないのに直さない、という選択肢はないので、check に直すオプションは持たせない

---

## 2. 整形の仕方

- dprint-plugin-markdown を Rust のライブラリとしてバイナリに埋め込んで使う。Prettier を使わないのは、Node.js がいらず、docv の版で整形の結果が固定されるため
- 整形の形は docv が決め、設定では変えない。好みで揉めないことと、どのプロジェクトでも同じ形になることを優先する

| 対象           | 整形の形                                                              |
| -------------- | --------------------------------------------------------------------- |
| 文の折り返し   | 変えない。改行の位置はそのまま残す                                    |
| 空行           | ブロック（段落、見出し、リスト、表、コードブロック）の間を 1 行にする |
| 表             | 列の幅をそろえる。全角文字は 2 文字分として数える                     |
| 箇条書きの記号 | `-`                                                                   |
| 強調の記号     | 斜体は `*`、太字は `**`                                               |
| 見出し         | `#` の形                                                              |
| コードブロック | 中身は変えない。ただし行末の空白は消す                                |
| 行末           | 末尾の空白を消す。改行は LF にし、ファイルの最後に改行を 1 つ置く     |
| frontmatter    | 中身は変えない。本文との間を空行 1 行にする                           |

整形したファイルをもう一度整形しても、結果は変わらない。

---

## 3. textlint の自動修正

- lint.textlint.enabled が true なら、整形の前に textlint の自動修正（`textlint --fix`）をかける。使うルールは check と同じ（[spec/textlint.md](textlint.md)）
- 自動修正で直せないものは残る。残ったものは check で確かめる
- archive には textlint をかけない。archive は移した本文をそのまま残すため。整形はする
- textlint をかけるときだけ Node.js が必要になる。`--no-textlint` なら Node.js はいらない

---

## 4. ほかのコマンドとの関係

format.enabled が true のときは、次のように連動する。

| コマンド                  | 動き                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| `docv check`              | 整形が必要なファイルを、ルール ID format-diff の error として出す |
| `docv new`、`docv retire` | 整形してから書く。textlint の自動修正はかけない                   |

format.enabled が false でも、`docv fix` を直接実行すれば直せる。

---

## 5. エディタの自動整形

- エディタの Markdown の自動整形は切り、保存のときに `docv fix --no-textlint <ファイル>` を外部の整形ツールとして実行するように設定する
- AI Agent には、ファイルを編集するたびに hook で `docv fix <ファイル>` と `docv check <ファイル>` を実行させるとよい。hook は利用者が設定する
