# frontmatter

管理対象のファイルの先頭に書く frontmatter の項目。どのファイルが管理対象かは [spec/config.md](config.md)、種類は [spec/kind.md](kind.md)。

---

## 1. 項目

| key      | 対象         | 必須 | 中身                                                         |
| -------- | ------------ | ---- | ------------------------------------------------------------ |
| question | すべての種類 | 必須 | このファイルが答える問い（1 文）                             |
| topics   | すべての種類 | 任意 | docv.yaml の topics に定義した話題のリスト                   |
| status   | plan         | 必須 | todo / doing                                                 |
| source   | archive      | 必須 | 移した元のファイルのパス（リポジトリのルートからの相対パス） |

```yaml
---
question: 注文の処理は、どの注文をいつ確定し、失敗したときにどう扱うか
topics: [注文]
---
```

---

## 2. question の書き方

- 1 文の、疑問の形で書く（〜は何か、どう〜か）
- ファイルの中身は、この問いへの答えだけにする
- HTML と `docv index` は、この問いをファイルの説明として表示する。タイトルとは別に、「このファイルを読むと何が分かるか」が伝わるように書く

| 良い                                                         | 悪い                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------------- |
| 注文の処理は、どの注文をいつ確定し、失敗したときにどう扱うか | 注文の処理について（問いになっておらず、範囲が決まらない） |
| 決済サービスに何にいくらかかり、費用を理由に何を決めているか | 費用まわり全般（どこまで書くかが決まらない）               |

---

## 3. docv.yaml で与える

- frontmatter を書けないファイル（README.md など）は、docv.yaml の docs の項目に question と topics を書ける
- docv.yaml で与えられるのは、path にワイルドカードを含まない項目（1 ファイルだけに当てはまる項目）だけ
- frontmatter と docv.yaml の両方に question があるときは、check がエラーにする

---

## 4. それ以外の key

- docv が知らない key は、そのまま残し、check もしない
- 作成者の記録（created / updated など）のように、プロジェクトの規約で決めた key を書いてよい
