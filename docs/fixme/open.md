# 未決事項

docv の設計のうち、まだ決まっていないこと。決まったら答えを `spec/` に書き、ここから消す。

---

## 1. リンクのアンカーを check するか

HTML の見出しには GitHub と同じ形のアンカーを付けているので、同じ規則で check もできる。

---

## 2. 違うマシンでも同じ JPG にするか

同じにするには、フォントを埋め込む必要がある。日本語のフォントはサイズが大きい。

---

## 3. 過去の言い回しの既定の語は何がいいか

`rule/docs/guideline.md` の 10 章の語を docs にかけて、誤検知と見逃しを見る。

---

## 4. 名前

docv は仮の名前。

---

## 5. textlint の組み込みのプリセットで、docv の既定で切っておくルールはあるか

たとえば、箇条書きの文末に句点を求めるルールや、全角と半角の間にスペースを入れないことを求めるルールは、docs の書き方とぶつかりやすい。

ja-spacing の ja-space-around-code、ja-space-around-link、ja-no-space-around-slash は、既定では前後の空白を消す。`docv fix` の自動修正で、インラインコード、リンク、スラッシュの前後が詰まる。このリポジトリでは `docv.yaml` で設定を変えている。

---

## 6. Slot のファイルからスキーマを参照させるか

YAML の Slot のスキーマは `docv schema <slot>` で出せる。`docv.yaml` と同じように、Slot のファイルの先頭に yaml-language-server の書式で URL を書けば、エディタで補完と検証を効かせられる見込みがある。YAML で書いたスキーマをエディタが読めるかは、確かめていない。決まっていないのは、docv add がその行を書くかと、check をスキーマで確かめるか。今の check は Slot の型で確かめていて、スキーマと 2 か所で揃えている。

---

## 7. HTML に全文検索を置くか

HTML には検索がなく、ページ内の検索か、最後の原本のツリーを目で探す。検索を置くには、検索用の索引と JS を出力に含める必要がある。JPG では検索は使えない。

---

## 8. 図のファイルがないとき、サービス仕様の部品を docv が図にするか

サービス仕様の部品と依存（`depends`）から、docv が SVG を描けば、図の道具がなくても全体が見える。配置を毎回同じにする規則が要る。
