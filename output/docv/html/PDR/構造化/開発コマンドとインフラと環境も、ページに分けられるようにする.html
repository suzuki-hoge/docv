開発コマンドとインフラと環境も、ページに分けられるようにする

背景

ページに分けられるのは、サービス仕様とシステム仕様だけだった。画面、サーバ、バッチのように部品ごとに開発のコマンドや環境が違うプロジェクトでは、開発コマンドとインフラと環境も、部品ごとの記述が 1 つのページに並んで長くなる。開発コマンドは YAML の Slot で、md の Slot のように h1 をページの名前にできない。

決めたこと

開発コマンド（guide/develop/）とインフラと環境（operation/infrastructure/）も、1 つのファイルの代わりに、1 ページ 1 つのファイルで置けるようにする。ページの拡張子は、分けないときと同じにする。

  • インフラと環境は md なので、サービス仕様とシステム仕様と同じく、YAML front matter に order と mission を書き、本文の h1 をページの名前にする
  • 開発コマンドは、分けないときの項目に、order とページの名前の title を足す。スキーマは分けないときと同じものを使い、order と title は一緒に書く
  • order とページの名前の重なりは、同じ Slot のページどうしでだけ確かめる

結果

部品ごとにコマンドや環境が違うプロジェクトでも、ページを分けて読める。YAML のページは、ページごとに JPG を作り、インデックスからもページごとの JPG にリンクする。開発コマンドのスキーマが変わるので、版を上げてタグを打つまで、エディタは前の版のスキーマで確かめる。

見直す条件

  • 利用マニュアルや API 仕様書など、まだ分けられない md の Slot でも、1 つのページが長くなり、分けたいという要望が出たとき
  • 用語集や環境変数など、開発コマンドのほかの YAML の Slot でも、ページに分けたいという要望が出たとき

選ばなかった案

案選ばなかった理由
開発コマンドのページの名前を、ファイル名にするページのファイル名は自由に付ける決まりで、ほかの分けたページとも揃わない
開発コマンドのページに、分けないときと別のスキーマを用意する同じ項目を 2 つのスキーマで持つことになる
どの Slot も、ページに分けられるようにする分ける要望のない Slot まで、ページの決まりを持つことになる
