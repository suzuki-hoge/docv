docv/pdr/diff-open.md

コミットする前のドキュメントの変わり方を、docv diff-open で見る

背景

実装に合わせてドキュメントを書き換えると、どのドキュメントがどう変わったかが分かりにくい。git diff はファイルの行の差分を出すが、HTML のどのページ、どのカードに当たるかは分からない。「このままコミットしたら、ドキュメントのどこが変わるか」を、普段見ている HTML の形で見たい。

見たくなるのは、大きな変更をしたときと、docv の版を上げたときだと見込む。

決めたこと

  • docv diff-open [--from <rev>] を足す。--from のリビジョン（省略すると HEAD）と作業ツリーを比べ、HTML を作ってブラウザで開くまでを、1 回で行う
    • 作ると開くを分けない。ドキュメントを書き換えても開いているページは変わらず、見るたびに作り直すため
  • 比べるのは、ドキュメントの元のファイル（Markdown と YAML）にする。HTML どうしは比べない
    • --from のリビジョンは、今の docv では build できないことがある。docv の版を上げたときが、それに当たる
    • HTML を git で管理していないプロジェクトもある
  • ページの中には差分を出さず、ファイルごとに印を付けるだけにする。詳しい差分は、元のファイルのパスの代わりに出す git diff のコマンドで見てもらう
    • ページの中に差分を出すには、ページの HTML どうしを比べることになるため
  • 印は、新規、変更、削除の 3 つにする
    • 新規はページを全部読み、変更は差分を読み、削除は消してよいかを確かめる。見た人のすることが違うので、見た目を分ける
    • 足した行と消した行で印を分けても、見た人のすることは変わらない。消すだけの変更は、ほとんど起きない
    • 新規と削除はカードや行に色を付けて示し、変更は印を付けて、マウスを乗せると行数を出す
  • 消したファイルも、カード、箱、行として出す。ADR と Slot を消すことは普段ないので、消したときは目立たせるため
  • HTML は OS のキャッシュのディレクトリに書き、dir.output には書かない。出力を git で管理するリポジトリで、差分の HTML をコミットしないため

決めないこと

  • 画像だけを変えたときに、その画像を使うページに印を付けるかは決めない。使ってみて要ると分かったら、別の PDR で決める
  • --from に渡したブランチと、作業ツリーとの分かれ目（merge-base）で比べるかは決めない。今は --from のコミットそのものと比べる

結果

コミットする前に、変わったページを普段の HTML の形で見られる。docv の版を上げたときも、上げる前のコミットと比べられる。

中身の差分は、ブラウザでは見られない。git diff のコマンドをコピーして、端末で見る。

git の管理下にないプロジェクトでは使えない。docv open と同じく、macOS と Windows のほかでは使えない。

見直す条件

  • 印だけでは足りず、ページの中の差分を HTML で見たいという Issue が立ったとき
  • ブランチを --from に渡すと、ブランチで変えていないファイルにまで印が付くという Issue が立ったとき

選ばなかった案

案選ばなかった理由
build のたびに差分を取り、出力に印を付ける出力が git の状態で変わり、入力が同じなら同じ出力にする決まりに反する。出力をコミットするリポジトリに印が残る
ページの中で、足した行と消した行に色を付け、切り替えで消すHTML どうしを比べることになり、--from が今の docv で build できないと作れない
document_root に絞って git diff を出すラッパー変わったファイルが、HTML のどのページ、どのカードに当たるかが分からない
足した行と消した行で、+ と − の印を分ける見た人のすることが変わらない
新規にも、変更と同じ印を付ける新規はページを全部読み、変更は差分を読む。することが違う
