インストール

前提とされるもの

名前版何に使うか
Node.jstextlint を使うときだけ要る。docv check --no-textlint なら要らない
Google ChromeJPG を作るときだけ要る

手順

バイナリを取る

Windows

GitHub Release から docv-1.4.0-x86_64-pc-windows-msvc.zip を取り、展開した docv.exe を PATH の通った場所に置く。

macOS

GitHub Release からバイナリを取り、パスの通った場所に置く。arm64 の例。

curl -L https://github.com/suzuki-hoge/docv/releases/download/v1.4.0/docv-1.4.0-aarch64-apple-darwin.tar.gz | tar xz
mv docv /usr/local/bin/

ブラウザでダウンロードしたバイナリは、macOS の Gatekeeper に止められることがある。curl で取れば止められない。

Linux

GitHub Release からバイナリを取り、パスの通った場所に置く。x86_64 の例。

curl -L https://github.com/suzuki-hoge/docv/releases/download/v1.4.0/docv-1.4.0-x86_64-unknown-linux-musl.tar.gz | tar xz
mv docv /usr/local/bin/

ソースから入れる（Rust の環境があるとき）

cargo install --git https://github.com/suzuki-hoge/docv

手元のソースから入れる（Rust の環境があるとき）

クローンしたリポジトリや、手を入れている作業中のソースから入れる。リポジトリのルートで実行する。

cargo install --path .

~/.cargo/bin/docv に入る。ソースを変えたら、もう一度実行すると入れ直せる。
