サービス仕様

概要SlotFreeADRPDR設定ファイルコマンドビジュアライズ

docv build が作る HTML、JPG、インデックスの作り。HTML は dir.output の下の html/ に、JPG は image/ に、インデックスは document_root の直下の README.md に書く。以下、出力先は html/ を指す。

1. HTML の作り

  • CSS と JS は、出力先の直下の docv.css と docv.js に書き、各ページから相対パスで読む。ページの中には書かない。出力先をコミットするリポジトリで、CSS や JS を変えたときの差分を 1 ファイルに収めるため。外部の CDN は使わない。file:// で開いても、ホスティングしても見られる。画像は元のファイルを読むので、ホスティングするときは、画像を置いた document_root も含めて公開する
  • JS は、決定のページのカーソルキーでの移動、Free のページのタグのトグル、検索のページ、元のファイルのパスのコピーにだけ使う。JS が動かなくても、すべての中身は読め、リンクから辿れる。コピーのボタンは JS が動くときだけ出し、JPG には写さない。OS ごとの手順のタブは、JS を使わず CSS で切り替える。ページに分けた Slot のタブは、ページへのリンクにする
  • 出力するファイルとディレクトリの名前からは、空白を除く。Slot、ページに分けた Slot、ADR、PDR、Free ファイルのページと JPG のどれも同じ。たとえば、Doc ガイドのページは 開発者向けガイド/Docガイド.html、題が「Go にする」の決定は ADR/<group>/Goにする.html になる。CLI や git で、引用符なしでパスを扱えるようにするため。Free ファイルのページは、元のパスのディレクトリの名前からも空白を除く
  • すべてのページの左に、README とトップの 7 ページへのサイドバーを、右に、そのページの h2 と h3 の目次を置く。見出しのないページでは、目次の代わりに同じ幅の空きを置き、ページを移っても本文の位置を変えない。幅の狭い画面では、左のサイドバーを本文の上に置き、項目を折り返して並べる。印刷の表示（JPG）では、どちらのサイドバーも出さない
  • サイドバーには、次の 3 つの段の順に項目を並べ、段の間に横線を引く。項目の名前は、サイドバーの幅で折り返さないように短くする。README は、そのページがあるときだけ出す。ADR と PDR は、決定があるときだけ出す
    • ドキュメント: README、Slot、Free、ADR、PDR
    • docv が作るもの: Index、Config
    • Search
  • 左のサイドバーの一番下に、作った docv の版を Generated by docv <版> の形で出す。どの版の docv で作ったページかを、見て分かるようにするため
  • トップの 7 ページは、サイドバーと同じページの名前を h1 にする。ただし ADR の h1 は Architecture Decision Record、PDR の h1 は Product Decision Record で、略さずに書く。サイドバーは幅へ収まるよう略すが、ページでは何の記録かを読んで分かるようにするため
  • トップのページの HTML のファイルの名前は、Slot が index.html、Free が プロジェクト詳細.html、ADR が ADR.html、PDR が PDR.html。Index、Config、Search は、インデックス.html、現在の設定.html、検索.html
  • Slot、ADR、PDR、Free ファイルのページの h1 の上に、元のファイルのルートからのパスを小さく出し、横にパスをクリップボードにコピーするボタンを置く。ページを見て編集したくなったときに、元のファイルを見つけられるように。JPG にもパスは写す
  • 検索のページは、Slot ファイル、ADR、PDR、Free ファイルの中身を行ごとに並べた索引を、docv.js ではなく検索のページの中に書く。入力した文字列をそのまま含む行を探し、入力欄の下に、ファイルごとにパス、タグ、ヒットした行の前後 2 行を並べる。プレビューの長い行は、折り返さずに横へスクロールする。入力欄は、JS が動くときだけ出す
  • フェンスのコードブロックは、フェンスに書いた言語（yaml など）に合わせて、build のときに色を付ける。色は HTML の中に埋め込み、JS は使わない。言語がないか、docv が知らない言語なら、色を付けずに出す
  • リンクは、README、Free ファイル、Slot ファイル、ADR、PDR のページにだけ、出力先の中の相対パスで張る（ツリー、Slot ファイルや Free ファイルの本文の中のリンク）。file:// で開けば file:// のまま、ホスティングすればその中で辿れる。docv.yaml へのリンクは、現在の設定のページに向ける。HTML は clone したリポジトリで見るので、ほかのファイル（コード、管理外のファイルなど）はエディタで開けばよく、リンクにせず文字だけを出す
  • 本文の中の http:// と https:// で始まる URL は、[文字](URL) の形で書いていなくてもリンクにする。URL は、空白、<、>、ASCII でない文字の前で終わり、末尾の句読点と、対になっていない ) は含めない。日本語の文と続けて書いても、後ろの文を URL に含めないため。リンク、画像、コードの中の URL は変えない
  • 画像は、元のファイルを出力先から辿れる相対パスで読み、出力先にはコピーしない。出力先をコミットするリポジトリで、同じ画像を 2 か所に持たないため
  • 表のセルの中のインラインコードは、折り返さない。コマンドやパスが途中で切れないようにするため
  • 表が横にはみ出すときは、ページごと広げず、表の中だけを横にスクロールさせる
  • 本文の中のリンクには下線を付け、色だけでリンクを示さない。キーボードで移ったときは、どこにいるかを枠で示す

2. README のページ

  • ルートの README.md を、README.html のページにする。README.md がないか、docv_exclude に当てはまるときは作らない
  • README.md の h1 をページの h1 にし、本文の見出しは h2 から始まるように段を付け直す。見出しには、GitHub と同じ形のアンカーを付ける
  • README.md は管理外のままにする。check と fix はかけず、検索の索引にも入れない
  • README のページは JPG にしない。Markdown なので、GitHub でそのまま見られる

3. Slot のページ

  • Slot は 1 つずつ独立したページ（<まとまり>/<Slot>.html）にする。index.html（Slot）には、まとまりの見出しの下に、Slot のページの「一覧」の章の順で、すべての Slot のカードを横に並べる。画面の幅に収まらなければ折り返す。紙面を縦に使いすぎず、画像にしてもすべてのカードが写るため。置いていない Slot のカードは、グレーにし、破線の枠と「未作成」の文字を付けて、リンクにしない。どのミッションのドキュメントがないかを、色だけに頼らずに見せるため。カードの幅は固定し、画面の幅に合わせない。幅は、いちばん長い Slot の名前（7 文字）が折り返さない大きさ
  • Slot のカードと、Slot のページの見出しには、Slot ごとのアイコンを付ける。アイコンは、docv が Slot ごとに持つ線画の SVG で、外部の素材を使わない
  • Slot のページには、Slot の名前の見出しを出す。Slot のミッションは HTML には出さない。ミッションは、AI Agent がどの Slot に書くかを決める手がかりにする
  • 折りたたみは使わない。details も、Markdown の中の <details> も、開いて出す。画像にしても、すべての中身が読めるようにするため
  • 開閉するのは、OS ごとの手順のタブだけ。手順の中身が 1 つならタブにせず、複数なら書いた順にタブを並べる。JPG では、すべての OS の手順を並べて写す
  • ページに分けた Slot は、ページを 1 つずつ <まとまり>/<Slot>/<ページの名前>.html（サービス/サービス仕様/管理者向け機能.html など）にする。ページの名前は、md のページは h1、YAML のページは title。Slot の名前の見出しの下に、すべてのページへのリンクを order の順にタブとして並べ、開いているページのタブに印を付ける。タブの下の中身は、分けないときの Slot と同じ形で出す。カードは、先頭のページを開く
  • 用語集は、まとまりごとに name を h2 にし、items を「日本語 | 英語 | 意味」の表にする
  • 見た目に凝らない。中身は、見出し、段落、箇条書き、表だけで出す
  • ディレクトリは、1 つの表に 1 段だけを「名前 | 説明」で出し、入れ子は表を分けて出す。いちばん上の段の表を先に置き、下の段を持つディレクトリごとに、そのパスの h2 と、その下の 1 段の表を後ろに並べる。並びは、親の次にその子の順。下の段を持つディレクトリの名前は、その表へのページ内リンクにする。表の名前はコードの書式にし、h2 のパスはコードの書式にしない。名前の列の幅は、表どうしで揃える。入れ子を折りたたみで見せないのは、画像にしても読めるようにするため。entries に書いていない途中のディレクトリは、説明なしで出す
  • 見出しは、ページの先頭の h1（Slot の名前）が 1 つだけで、その下に h2 を並べる。段は飛ばさない（h1 の次に h3 や h4 を置かない）
    • Markdown（md の Slot、appendix_markdown、details、手順の中身）の見出しは、置く場所に合わせて段を付け直す。md の Slot と appendix_markdown は h2 から、details と開発コマンドの中身は h3 から、インストールと環境構築の手順の中身は h4 から
  • 手順（インストール、環境構築）は、「手順」の h2 の下に、項目ごとに h3 を並べる
  • 開発コマンドは、順番のない項目なので、先頭に目次（項目へのページ内リンク）を置き、各項目を h2 で始める
  • YAML の Slot の appendix_markdown は、スキーマで決めた項目のあとに続けて出す
  • md の Slot の見出しには、Free ファイルのページと同じく、GitHub と同じ形のアンカーを付ける。[docv init](#docv-init) のようなページ内リンクが HTML でも GitHub でも飛べる
  • md の Slot のページは JPG にしない。md は GitHub でそのままプレビューできるため

4. ADR と PDR のページ

ADR と PDR は、同じ作りのページにする。違うのは、一覧のページ（ADR.html と PDR.html）、決定のページの置き場所（ADR/ と PDR/）、題に付けるアイコンだけ。

  • ADR.html と PDR.html に、group ごとに h2 を置き、決定のつながりを、過去から未来へ左から右に箱と矢印で並べる。打ち消された決定の箱は、破線で薄く出す
  • 箱の幅はそろえ、題は箱の中で折り返す。つながりは 1 列に並べ、並びきらないときは、その列を横にスクロールする
  • つながりのない決定は、1 列に 1 つずつ並べず、まとまりのつながりの後ろに、箱を折り返して並べる。決定が増えても、ページが縦に伸びすぎないため
  • 箱は決定のカードで、クリックすると決定 1 つのページ（ADR/<group>/<title>.html か PDR/<group>/<title>.html）を開く。決定 1 つを 1 ページにする
  • 決定のページには、題を h1 にし、本文を出す。本文の見出しは h2 から始まるように段を付け直す。id と日付は出さない
  • 打ち消された決定のページには、h1 の下に、打ち消されたことと、打ち消した新しい決定へのリンクを出す。下のカードまで読まなくても分かるように
  • ADR と PDR のページは JPG にしない。どちらも Markdown なので、GitHub でそのまま見られる
  • 決定のページの下に、前後の決定をカードで出す。打ち消した過去の決定は「← 過去の決定」の見出しを付けて左に、この決定を打ち消した新しい決定は「新しい決定 →」の見出しを付けて右に置く。新しい決定へのつながりは、生成するときに supersedes を逆にたどって組み立てる
  • カーソルキーの ← と → で、前後の決定のページに移れる。前後に決定が複数あるときは、先頭のカードのページに移る。移れることは、カードの下に書く
言語
+-----------+   +-------------+
| Go にする | → | Rust にする |
+-----------+   +-------------+
+--------------+  +---------------+
| React にする |  | Python も使う |
+--------------+  +---------------+

5. 現在の設定のページ

docv build は、HTML の「現在の設定」のページに、docv.yaml のすべての項目と今の値を 1 つの表で並べる。何を設定でき、どれが効いているかを、スキーマを読まずに見るためのページ。

  • ページの名前の h1 の下に、項目の表を「docv.yaml」の h2 で置く
  • 項目は、dir.output のように、キーを . でつないだ名前で出す。並びは、スキーマの順
  • 書いていない項目は、既定の値で出す。値のない項目は - を出す
  • 配列の項目は、要素を箇条書きにする
  • 選ぶ項目（true か false、allow か deny など）は、候補を横に並べ、選んでいる候補に色を付ける
  • 表の後に、textlint の検査項目と非検査項目（設定ファイル のページの「textlint」の章）を、それぞれ表で並べる
  • Slot ファイルや Free ファイルから docv.yaml へのリンクは、HTML ではこのページに向ける

6. 毎回同じ出力にする決まり

  • 生成日時、実行したマシンのパス、乱数を出力に入れない
  • 並び順を固定する。Slot は規格の順（ページに分けた Slot のページは order とパスの順）、Free ファイルはディレクトリのツリーの順、Slot の中の項目は書いた順にする。ADR と PDR は日付と id の順。検索の索引は、Slot ファイル、ADR、PDR、Free ファイルの順
  • 入力（管理対象のファイル、README.md、Slot、ADR、PDR、docv.yaml、docv の版）が同じなら、HTML、docv.css、docv.js、インデックスはバイト単位で同じになる
  • JPG は、同じマシン・同じ Chrome・同じフォントなら同じになる。違うマシンで同じにすることはしない。チームで JPG を共有するなら、GitHub Actions などの決まった環境で作る

7. JPG

  • generate.image が true のときだけ、build の最後に作る。--no-image を付けると作らない
  • YAML の Slot のページを 1 枚ずつ、dir.output の下の image/ に <まとまり>/<Slot>.jpg の名前で置く。ページに分けた YAML の Slot は、ページを 1 枚ずつ <まとまり>/<Slot>/<ページの名前>.jpg の名前で置く
  • 幅は 1280 CSS ピクセル、画質は 80。印刷の表示で、ページ全体を 1 枚に写す
  • Chrome は、環境変数 DOCV_CHROME、OS ごとの標準のインストール先、PATH にある chrome と chromium の順に探す。見つからなければ error で終わる

8. インデックス

build は、毎回 document_root の直下に README.md を書く。GitHub でリポジトリを開いた人が、clone しなくても Slot ファイルを読めるようにするためのリンク集。名前を README.md にするのは、GitHub で document_root を開くと、一覧の下に表示されるため。ルートの README からリンクして使う。

  • Slot を、HTML の Slot のページ（index.html）と同じく、まとまりごとに規格の順で、リンクの箇条書きにして並べる。ページに分けた Slot は、Slot の名前の下に、ページを order の順に入れ子で並べる。置いていない Slot は出さない
  • md の Slot は、元のファイルへリンクする。GitHub で Markdown のまま読めるため。ファイルがシンボリックリンクなら、ルートの中にある先のファイルへリンクする。GitHub は、シンボリックリンクを開いても先の中身を出さないため
  • YAML の Slot は、generate.image が true なら JPG へリンクし、false なら出さない。分けたページも同じで、ページごとの JPG へリンクする。JPG へリンクするかは generate.image で決め、--no-image を付けても同じインデックスにする
  • Free ファイル、ADR、PDR は、それぞれの章に、置いているディレクトリへのリンクだけを出す。どれも詳細やプロジェクト固有の情報で、知りたくなった人は clone すると考えるため。検索とタグでの絞り込みは Free のページで、ADR と PDR のつながりの図はそれぞれのページで見られると、docv open と、そのページのルートからのパスで案内する
  • リンクは、README.md の場所からの相対パスで、[名前](<パス>) の形で書く。パスに空白や日本語が入っても、GitHub で辿れるようにするため
  • 1 行目に、docv が作ったことを示すコメントを書く。build は、このコメントで始まらない README.md を書き換えない（コマンド のページの「ファイルを書くコマンド」の章）
  • 末尾に、作った docv の版を Generated by docv <版> の形で書く。GitHub で見ても、docv が作ったファイルであり、手で直すものではないと分かるようにするため
  • インデックスが古いままかは、check で確かめない。Slot を変えたら build で作り直す
  • エイリアス（シンボリックリンク）やコピーを並べたディレクトリは作らない。GitHub はシンボリックリンクの先を出さず、コピーは同じ中身を 2 か所で持つことになり、md の中の相対リンクも壊れるため
  • HTML にも、インデックスと同じ並びの Index のページを作る。リンクは、md や JPG ではなく、HTML のページに向ける。YAML の Slot は、generate.image によらず、すべて並べる。Free ファイル、ADR、PDR は、それぞれの一覧のページへリンクする
