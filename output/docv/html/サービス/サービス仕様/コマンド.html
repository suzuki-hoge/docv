サービス仕様

概要SlotFreeADRPDR設定ファイルコマンドビジュアライズ

どのコマンドにも共通する決まり。コマンドごとの使い方は、利用マニュアル。

1. ルートと出力

  • docv ルートで実行するコマンド（利用マニュアルのコマンド一覧）は、カレントディレクトリをルートにし、そこにある docv.yaml を読む。親のディレクトリは探さない
  • 結果は標準出力に、エラーは標準エラーに出す

2. ファイルを書くコマンド

コマンド書くもの
initdocv.yaml だけ。--print のときは書かない
slot gen指定した Slot ファイルだけ。--print のときは書かない
fix管理対象のファイル、dir.slot の中の Markdown（md の Slot、ADR、PDR）、YAML の Slot だけ。整形と textlint の自動修正だけをする。YAML の Slot は、Markdown の項目の中身だけを直す。docv.yaml と YAML の Slot は、末尾の改行も整える
builddir.html と dir.image の中と、dir.index を書いたときの docv-index.md だけ。出力先は、目印の .docv を残して中を消し、作り直す。--no-image のときは dir.image に触れない
  • ほかのコマンドは、ファイルを書かない
  • CLAUDE.md、リポジトリのルートの .gitignore、hook の設定は、どのコマンドも書かない
  • build は、出力先に .docv（docv が作った目印）がなく、空でもないときは、何も書かずにエラーで終わる。dir.html や dir.image を間違えて既存のディレクトリを指しても消さないため
  • build は、すでにある docv-index.md の 1 行目に docv の印のコメントがないときも、何も書かずにエラーで終わる。手で書いた同じ名前のファイルを消さないため
  • dir.index を消しても、build は docv-index.md を消さない

3. 終了コード

コード意味
0成功。check で指摘が 1 件もない
1check で指摘（error）が 1 件以上ある。fix で直せないファイルがある。open に対応していない OS
2docv.yaml がスキーマに合わない、引数が正しくない、など実行できない

4. 言語

CLI のメッセージ、ヘルプ、docv の概要、テンプレは、日本語だけで書く。切り替えはできない。英語に訳した版を持つと、同じことを 2 か所で揃え続けることになるため。
