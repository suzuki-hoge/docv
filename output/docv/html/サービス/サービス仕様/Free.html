サービス仕様

概要SlotFreeADR設定ファイルコマンドビジュアライズ

docv が管理する Free ファイル（docv.yaml の dir.free のディレクトリの下の Markdown）のルール。何をどう書くかはガイドライン（Slot の Doc ガイド、guide/doc-guide.md）で、プロジェクトが決める。Slot のルールは Slot、ADR のルールは ADR、docv.yaml は 設定ファイル のページに書く。

1. YAML front matter

key必須中身
mission必須ミッション。このファイルを読むと何が分かるか（1 文）
tags任意タグの配列（「タグ」の章）
---
mission: 注文を確定するタイミングと、失敗したときの扱い
tags: [仕様, 注文]
---
  • mission は 1 行で書く
  • ファイルごとの設定は、すべて YAML front matter に書き、docv.yaml には書かない。ファイルを動かしても設定がずれず、AI Agent はファイルを読むだけで、そのファイルの扱いが分かる
  • docv が知らない key は、そのまま残し、check もしない。作成者の記録（created / updated など）のように、プロジェクトが決めた key を書いてよい
  • HTML は、mission をファイルの説明として表示する

2. タグ

  • Free ファイルの分類は、YAML front matter の tags に書くタグで行う。1 つのファイルにいくつでも付けられる
  • docv はタグの意味を決めない。どんなタグを使うかは、プロジェクトが決める
  • 使うタグは、すべて docv.yaml の tags に書く。tags にないタグを付けると、check が error にする
  • tags には、タグごとに名前（name）と色（color）を書く。色は HTML でタグを見分けるためのもので、blue、green、yellow、red、purple、orange、teal、pink から選ぶ
tags:
  - name: 仕様
    color: blue
  - name: 計画
    color: green

3. check のルール

docv check が Free ファイルで確かめるルール。docv.yaml で使うと決めたときだけ確かめるもの（太字などの書式の規則、整形、textlint）は 設定ファイル のページに書く。

構造とリンク

ID内容
title-counth1 が 1 つでない
heading-number章番号で始まる h2 があるのに、h2 が 1. から順に章番号で始まっていない
link-brokenルートの中を指す相対リンクの先にファイルがない
link-anchorリンクのアンカー（# 以降）が指す見出しが、リンク先の Markdown にない
  • 章番号は、h2 のどれかが 1. のような章番号で始まっているファイルでだけ確かめる。章番号を使わないファイルでは確かめない
  • アンカーは、HTML の見出しと同じく GitHub と同じ形で作る。同じ見出しが続けば -1、-2 を付ける。# だけのページ内リンクは、そのファイルの見出しと比べる。Markdown でないファイルへのリンクのアンカーは確かめない
