docv/adr/assets-only.md

実装から参照して出力するものを assets/ にまとめる

背景

バイナリに埋め込むものが、3 か所に分かれていた。

  • templates/: YAML の Slot のサンプル
  • schema/: docv.yaml のスキーマ
  • assets/: CSS、docv の概要、YAML の Slot のスキーマ

利用側が書き換えるかどうかや、公開するかどうかで分けていた。しかし、どれも実装から参照して出力するものという点で同じ。

決めたこと

実装から参照して出力するものは、すべて assets/ に置く。YAML の Slot のサンプルは assets/template/、docv.yaml のスキーマは assets/schema/docv.schema.json に置く。templates/ と schema/ はなくす。

結果

埋め込むものは assets/ を見れば揃う。docv.yaml から参照するスキーマの URL は .../v<版>/assets/schema/docv.schema.json になる。タグを付けた版の URL は、その版の中身を指すので変わらない。

選ばなかった案

案選ばなかった理由
利用側に書くもの（サンプル）を分けて置く書き換えるかどうかは利用側の扱いで、実装の置き場所とは関係がない
公開するスキーマだけをルートの schema/ に残す公開は URL で参照するだけで、置き場所を分ける理由にならない
