docv/adr/search.md

HTML に、入力した文字列をそのまま探す検索のページを置く

背景

HTML でドキュメントを探す手段は、ブラウザのページ内検索だけで、1 ページの中しか探せなかった。HTML は file:// で開いても見られ、外部の CDN を使わず、JS が動かなくても中身を読める決まりがある。file:// では fetch() でファイルを読めない。

決めたこと

トップに検索のページを置き、サイドバーから開く。build は、Slot ファイル、ADR、Free ファイルの中身を行ごとに並べた索引を、検索のページの中に書く。JS は、入力した文字列をそのまま含む行を総当たりで探し、入力欄の下に、ファイルごとにパス、タグ、ヒットした行の前後 2 行を並べる。入力欄は、JS が動くときだけ出す。

結果

単語に区切らないので、日本語もそのまま探せ、ライブラリも要らない。あいまい検索と、関係が深い順の並べ替えはできない。索引は中身をすべて持つので、ドキュメントが増えるほど検索のページが大きくなる。

選ばなかった案

案選ばなかった理由
JS の全文検索のライブラリを埋め込む日本語を単語に区切る工夫が要る。順位付けやあいまい検索は、まだ要らない
静的サイト向けの検索ツールで索引を作る索引を fetch で読むので、file:// で動かない。別のツールのインストールも要る
索引を別の JS ファイルに書き出す索引を読むのは検索のページだけで、ファイルを分ける理由がない
build で単語から行を引く表（転置索引）を作る総当たりで足りる量では、表を作る手間に見合わない。区切り方を Rust と JS で揃える必要もある
