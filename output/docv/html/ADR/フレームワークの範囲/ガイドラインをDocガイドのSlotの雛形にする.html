docv/adr/doc-guide.md

ガイドラインを Doc ガイドの Slot の雛形にする

背景

Free ファイルの書き方は、このリポジトリの docs/rule/docs/guideline.md にだけあり、利用側には届かなかった。届けるとしても、ドキュメントを書くときの方針はプロジェクトごとに調整したい。一方で、YAML front matter の key や check のように、docv の仕組みが決めるものは変えられない。

決めたこと

docv の決まりを、次の 3 つに分ける。

  • ルール: docv の仕組みが決めるもの。docv desc と docv schema で見る
  • 設定: docv.yaml で切り替えるもの
  • ガイドライン: ドキュメントを書くときの方針で、利用側が調整するもの

ガイドラインは、開発者向けガイドの Slot「Doc ガイド」（guide/doc-guide.md）に書く。docv add doc-guide は、docv が勧めるガイドラインの雛形を書き、作った後は利用側が自由に直す。docv add doc-guide --print で、今の版の雛形を出せる。Free ファイルのルールは、docs/spec/free.md に分ける。docv 自身の Doc ガイドは、このリポジトリに合わせて直したもので、雛形とは一致させない。

結果

利用側は、ルールを docv の版と一緒に受け取り、ガイドラインは自分のものとして直せる。Doc ガイドは置き場所が決まっているので、AI Agent が見つけられ、HTML にもカードで出る。雛形を直しても、利用側の Doc ガイドには届かない。差分は --print で見比べる。

選ばなかった案

案選ばなかった理由
ガイドラインを docv desc に入れる利用側が調整できない
基本のガイドラインに、利用側の差分を重ねて出す差分で指せるように、ガイドラインに ID を振る設計が重い
ガイドラインの項目を、docv.yaml でオンとオフにする文章の方針を細かい項目に切り分けられず、言い換えもできない
docv init で、雛形を好きな場所に書き出すdocv.yaml があるプロジェクトでは作れない。AI Agent が置き場所を知れない
docv 自身の Doc ガイドを、雛形へのシンボリックリンクにするこのリポジトリに合わせて直せない
Slot の名前を「ガイドライン」か「ドキュメント」にする何のガイドラインか分からない。Slot もすべてドキュメントで、区別にならない
