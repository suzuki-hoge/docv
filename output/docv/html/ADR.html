ADR

破線の箱は、新しい決定に打ち消された決定。

記録

外した内容は理由と一緒に archive に移す→決めた経緯は ADR で記録する
docv 自身の設計は Slot に書き、spec には規格の詳細だけを残す→docv のサービス仕様をページに分け、1 ページ目を docv desc と同じファイルにする
docv で版を管理しない

コマンド

整形は docv fmt で行う→整形と textlint の自動修正を docv fix にまとめる
Slot のファイルは、パスではなく Slot の名前で作るAI Agent 向けの一覧を出すコマンドを持たない後から入れるときのガイドを出すコマンドを持たないYAML の Slot のスキーマを docv schema で出すSlot のディレクトリの Markdown も整形するSlot のディレクトリでも除外のルールを守るコマンドを init、desc、check、fix、build、slot に組み直すcheck にパスを渡しても、かける検査を変えないmd の Slot と ADR にも、Free ファイルと同じ検査をかけるdocv fix で YAML のファイルの末尾の改行を整えるリンクのアンカーを check で確かめるcheck の指摘の強さをなくし、すべて error にするリンクの表示文字の規則をやめる

構造化

ドキュメントを組み込みの種類と時間で分ける→種類をやめ、任意の数を付けられるタグで分ける→使うタグを、色と一緒に docv.yaml に書く
docv が読み書きするディレクトリを dir にまとめる→dir の 4 つのディレクトリを互いに離し、HTML の既定を output/docv/html にする
YAML の Slot の body と include をなくす→YAML の Slot に appendix_markdown を書けるようにする
サービス概要の Slot を足し、サービス仕様と分ける→サービス仕様とシステム仕様を、実装を差し替えても変わらないかで分ける→システム概要の Slot を足し、システム仕様と分ける
サービス仕様をページに分けられるようにする→システム仕様も、サービス仕様と同じくページに分けられるようにする
構造化は YAML front matter と docv.yaml に限る規格のファイルを Slot と呼ぶデプロイとリリースを別の md の Slot にする利用マニュアルを md の Slot にする原本を Free ファイルと呼び変えるAPI 仕様書と DB 仕様書を md だけにするファイルが扱うことをミッションと呼び、読むと何が分かるかで書くまだ決まっていないことを docs/plan に置くYAML の Slot の Markdown は、_markdown で終わる項目に | で書き、検査するSlot のまとまりの名前を、サービスとシステムにするmd の Slot の YAML front matter に、ミッションを必ず書く

フレームワークの範囲

check と HTML の生成はローカルで完結させる実装とドキュメントのずれを検出しないAI Agent にはルールファイルを渡すところまでにするdocv desc はサービス仕様と同じ docv の概要を出すガイドラインを Doc ガイドの Slot の雛形にするcheck の設定を太字、斜体、$、textlint の 4 つにするサービス仕様の図を docv が描かないtextlint のルールと値を docv が決める

配布

GitHub Actions で各プラットフォーム向けにビルドするRust で書く実装から参照して出力するものを assets/ にまとめるDoc ガイドの雛形は、開発の手順で docv fix と docv check にかける名前を docv にするスキーマを JSON に揃え、YAML の Slot の 1 行目から参照する

出力

すべてのページの右に目次を置く→目次のないページにも、目次の幅を空けておく
原本も HTML のページにするHTML のコードブロックに build のときに色を付けるディレクトリのページを 1 段ずつの表に分けるHTML のリンクはページにだけ張るSlot のカードを折り返して並べるdocv.yaml へのリンクを、現在の設定のページに向ける現在の設定を HTML のページで見せるJPG を違うマシンで揃えず、build --no-image で作らずに済ませるHTML に、入力した文字列をそのまま探す検索のページを置く本文にそのまま書いた URL も、HTML でリンクにする
