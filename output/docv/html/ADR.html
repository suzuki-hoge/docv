記録

外した内容は理由と一緒に archive に移す→決めた経緯は ADR で記録する
docv で版を管理しない
docv 自身の設計は Slot に書き、spec には規格の詳細だけを残す→docv のサービス仕様をページに分け、1 ページ目を docv desc と同じファイルにする

コマンド

整形は docv fmt で行う→整形と textlint の自動修正を docv fix にまとめる
Slot のファイルは、パスではなく Slot の名前で作る
AI Agent 向けの一覧を出すコマンドを持たない
後から入れるときのガイドを出すコマンドを持たない
YAML の Slot のスキーマを docv schema で出す
Slot のディレクトリの Markdown も整形する
Slot のディレクトリでも除外のルールを守る
コマンドを init、desc、check、fix、build、slot に組み直す
check にパスを渡しても、かける検査を変えない
md の Slot と ADR にも、Free ファイルと同じ検査をかける
docv fix で YAML のファイルの末尾の改行を整える
リンクのアンカーを check で確かめる
check の指摘の強さをなくし、すべて error にする
リンクの表示文字の規則をやめる

構造化

ドキュメントを組み込みの種類と時間で分ける→種類をやめ、任意の数を付けられるタグで分ける→使うタグを、色と一緒に docv.yaml に書く
構造化は YAML front matter と docv.yaml に限る
規格のファイルを Slot と呼ぶ
デプロイとリリースを別の md の Slot にする
利用マニュアルを md の Slot にする
原本を Free ファイルと呼び変える
API 仕様書と DB 仕様書を md だけにする
ファイルが扱うことをミッションと呼び、読むと何が分かるかで書く
docv が読み書きするディレクトリを dir にまとめる→dir の 4 つのディレクトリを互いに離し、HTML の既定を output/docv/html にする
YAML の Slot の body と include をなくす→YAML の Slot に appendix_markdown を書けるようにする
まだ決まっていないことを docs/plan に置く
YAML の Slot の Markdown は、_markdown で終わる項目に | で書き、検査する
サービス概要の Slot を足し、サービス仕様と分ける→サービス仕様とシステム仕様を、実装を差し替えても変わらないかで分ける→システム概要の Slot を足し、システム仕様と分ける
サービス仕様をページに分けられるようにする→システム仕様も、サービス仕様と同じくページに分けられるようにする
Slot のまとまりの名前を、サービスとシステムにする
md の Slot の YAML front matter に、ミッションを必ず書く

フレームワークの範囲

check と HTML の生成はローカルで完結させる
実装とドキュメントのずれを検出しない
AI Agent にはルールファイルを渡すところまでにする
docv desc はサービス仕様と同じ docv の概要を出す
ガイドラインを Doc ガイドの Slot の雛形にする
check の設定を太字、斜体、$、textlint の 4 つにする
サービス仕様の図を docv が描かない
textlint のルールと値を docv が決める

配布

GitHub Actions で各プラットフォーム向けにビルドする
Rust で書く
実装から参照して出力するものを assets/ にまとめる
Doc ガイドの雛形は、開発の手順で docv fix と docv check にかける
名前を docv にする
スキーマを JSON に揃え、YAML の Slot の 1 行目から参照する

出力

原本も HTML のページにする
HTML のコードブロックに build のときに色を付ける
ディレクトリのページを 1 段ずつの表に分ける
すべてのページの右に目次を置く→目次のないページにも、目次の幅を空けておく
HTML のリンクはページにだけ張る
Slot のカードを折り返して並べる
docv.yaml へのリンクを、現在の設定のページに向ける
現在の設定を HTML のページで見せる
JPG を違うマシンで揃えず、build --no-image で作らずに済ませる
HTML に、入力した文字列をそのまま探す検索のページを置く
本文にそのまま書いた URL も、HTML でリンクにする
