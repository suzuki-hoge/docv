# ページに関わる決定を YAML front matter に書き、ページの末尾に出す

## 背景

Slot と Free ファイルの決まりの文に、ADR や PDR へのリンクや、「理由は ADR に書いた」のような文が付いていた。ページの読者に要るのは今の決まりで、決定の経緯ではない。決定が打ち消されても、リンクは古い決定を指したまま残る。

一方で、決まりを変える人は、その決まりに関わる決定を知りたい。本文から消すだけでは、関わる決定を辿れなくなる。

## 決めたこと

ページの側の YAML front matter に、関わる決定の id を並べる。

- `adr` と `pdr` に、それぞれの id を並べる。ADR と PDR は、同じ id でも別の決定なので、項目を分ける
- md の Slot（分けたページも）と Free ファイルに書ける
- HTML では、docv がページの本文の後に、関わる決定の題を並べてリンクする
- 決定のページには、その決定を指しているページを逆に並べる
- ない id は、check が error にする
- 打ち消された決定を指していれば、check が warning にし、ページの末尾には出さない
  - 打ち消した新しい決定がページに関わるかは、docv には分からないため
- 本文では、ADR と PDR を案内しない

## 結果

- ページの読者は、決定の経緯を読まずに、今の決まりだけを読める
- 決まりを変える人は、ページの末尾から関わる決定を辿れ、決定のページからは、それが効いているページを辿れる
- 決定が打ち消されると、check の warning で、指しているページに気づける
- check に warning ができる。warning だけなら、終了コードは 0 にする

## 見直す条件

- ページの YAML front matter の `adr` と `pdr` が、1 つのプロジェクトで 10 を超えるページで、打ち消された決定を指したまま残っているとき
  - warning では直されないという合図になる

## 選ばなかった案

| 案                                         | 選ばなかった理由                                                       |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| 決定の側に、関わるページを書く             | 決定は書き換えないが、ページは移ったり分かれたりする                   |
| 本文のリンクのまま、check で古さを確かめる | 読者に要らない経緯が本文に残る。どこまでが案内かを機械では決められない |
| `adr` と `pdr` を 1 つの項目にまとめる     | ADR と PDR は、同じ id でも別の決定                                    |
