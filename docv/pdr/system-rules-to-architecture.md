# 部品をまたいで守る決まりを、システム仕様からアーキテクチャに移す

## 背景

システム仕様のミッションは「部品ごとの振る舞いと、部品の間の流れと、部品をまたいで守る決まり」だった。開発者向けガイドに足したアーキテクチャの Slot は、システム全体で採る方式と決まりを書く。部品をまたいで守る決まりは、システム全体で採る決まりと重なり、どちらに書くかがミッションだけでは決まらない。このリポジトリでも、アーキテクチャに書いた方式が、システム仕様の記述と重なった。

## 決めたこと

システム仕様のミッションを「部品ごとの振る舞いと、部品の間の流れ」にし、部品をまたいで守る決まりは、アーキテクチャに書く。

部品は、画面、サーバ、バッチ、DB、外部サービスなど、システムを作る単位を指す言葉として、システム概要、システム仕様、アーキテクチャのミッションで揃える。部品を軸にすると、次のように書き分けられる。

| Slot           | 書くこと                                       |
| -------------- | ---------------------------------------------- |
| システム概要   | どんな部品があるか                             |
| システム仕様   | 部品ごとに何をするか、部品の間で何が流れるか   |
| アーキテクチャ | 部品をどう分け、どうつなぎ、全体で何を揃えるか |
| 設計・実装     | 部品の中のコードをどう書くか                   |

## 結果

- システム仕様の `mission` が変わるので、すでにある md の Slot は、check の slot-mission の error で直す
- システム仕様に書いていた、部品をまたいで守る決まりは、アーキテクチャに移す。移したかどうかは、check では確かめない
- システム仕様は、個別の部品と流れを詳しく書く Slot になる。全体の方式を知りたい開発者は、アーキテクチャを読む

## 見直す条件

- アーキテクチャとシステム仕様のどちらに書くかで迷う記述が、繰り返し出たとき

## 選ばなかった案

| 案                                             | 選ばなかった理由                                                                                                                                                                                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 部品という言葉を使わずにミッションを書く       | 「システムの内部」のような言葉になり、どの Slot に書くかが決まらない。システム仕様のミッションが「システムの内部の動き」だったときも、サービス仕様と重なって書き直した（[サービス仕様とシステム仕様を、実装を差し替えても変わらないかで分ける](spec-boundary.md)） |
| 部品をまたいで守る決まりを、システム仕様に残す | アーキテクチャの決まりと重なり、ミッションだけでは書く場所が決まらない                                                                                                                                                                                             |
