# ディレクトリの Slot をやめる

## 背景

開発者向けガイドに、ディレクトリごとの役割を書くディレクトリの Slot（`guide/directory-tree.yaml`）があった。HTML では、パスを 1 段ずつの表に分けて出し、`path` の先がなくなると check が slot-path-missing の error にしていた。

このリポジトリで使ってみると、ディレクトリのページはほとんど開かれなかった。ディレクトリの名前と役割は、エディタやリポジトリのツリーを見れば分かることが多い。読む価値があるのは、どこに何を置くかの決まりのほうで、それはパスと役割の一覧の形には収まらない。

## 決めたこと

ディレクトリの Slot をやめる。Slot の定義、スキーマ、雛形、HTML の表を消す。ディレクトリについて書きたい決まりは、同じ版で足す設計・実装の Slot（`guide/design.md`）に書く。

## 結果

- すでにある `guide/directory-tree.yaml` は、check の slot-unknown の error になる。利用者は、残したい決まりを設計・実装に移し、ファイルを消す。docv update-guide で案内する
- ディレクトリの `path` の先がなくなったことに、check で気づけなくなる。ディレクトリの構成とドキュメントのずれは、機械では見つけない
- 公開したスキーマは版のタグの URL に残るので、前の版の docv を使うプロジェクトのエディタの補完は壊れない

## 見直す条件

- ディレクトリの構成とドキュメントのずれを、check で見つけたいという要望が出たとき

## 選ばなかった案

| 案                                                         | 選ばなかった理由                                                                                  |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| ディレクトリの Slot を残し、使わないプロジェクトは置かない | 置くかどうかは今も任意で、残しても開かれないページのために、書く手間と直す手間がかかり続ける      |
| ディレクトリの一覧を、設計・実装の YAML の項目にする       | 設計・実装は、決まりを自由な形で書く md の Slot。一覧の形を決めると、決まりの書き方を縛ってしまう |
