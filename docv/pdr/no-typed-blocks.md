# 構造化は YAML front matter と `docv.yaml` に限る

## 背景

費用やコマンドのように、決まった形で書きたい情報がある。Free ファイルの本文の中に、決まった形のブロックを書かせる方法もあった。

## 決めたこと

個々のファイルの本文には、細かい形の制約を入れない。決まった形で書くものは、docv の規格のファイル（Slot）にする。

## 結果

Free ファイルは、ふつうの Markdown として読み書きできる。決まった形で書きたい情報は、Slot を足して扱う。

## 見直す条件

- Slot にするほどではない決まった形の情報を、複数のプロジェクトが Free ファイルの本文に同じ形で書いているのを見つけたとき

## 選ばなかった案

| 案                                                       | 選ばなかった理由                                                |
| -------------------------------------------------------- | --------------------------------------------------------------- |
| 費用やコマンドを、本文の中の YAML のコードブロックで書く | 本文に細かい制約を入れると、Markdown として読み書きしにくくなる |
