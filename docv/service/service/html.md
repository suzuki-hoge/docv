# ビジュアライズ

`docv build` が作る HTML、JPG、インデックスの作り。

---

## 1. HTML の作り

- CSS は各ページの中に書く。外部の CDN は使わない。file:// で開いても、そのままホスティングしても見られる
- JS は、決定のページのカーソルキーでの移動、プロジェクト詳細のタグのトグル、検索のページにだけ使い、ページの中に書く。どれも JPG にしないページで、JS が動かなくても、すべての中身は読め、リンクから辿れる。OS ごとの手順のタブは、JS を使わず CSS で切り替える。分けたサービス仕様とシステム仕様のタブは、ページへのリンクにする
- すべてのページの左に、README とトップの 5 ページ（プロジェクト概要、ADR、プロジェクト詳細、現在の設定、検索）へのサイドバーを、右に、そのページの h2 と h3 の目次を置く。README は、そのページがあるときだけ先頭に出す。見出しのないページでは、目次の代わりに同じ幅の空きを置き、ページを移っても本文の位置を変えない。印刷の表示（JPG）では、どちらのサイドバーも出さない
- 検索のページは、Slot ファイル、ADR、Free ファイルの中身を行ごとに並べた索引を、ページの中に書く。入力した文字列をそのまま含む行を探し、入力欄の下に、ファイルごとにパス、タグ、ヒットした行の前後 2 行を並べる。プレビューの長い行は、折り返さずに横へスクロールする。入力欄は、JS が動くときだけ出す
- フェンスのコードブロックは、フェンスに書いた言語（`yaml` など）に合わせて、build のときに色を付ける。色は HTML の中に埋め込み、JS は使わない。言語がないか、docv が知らない言語なら、色を付けずに出す
- リンクは、README、Free ファイル、Slot ファイル、ADR のページにだけ、出力先の中の相対パスで張る（ツリー、Slot ファイルや Free ファイルの本文の中のリンク）。file:// で開けば file:// のまま、ホスティングすればその中で辿れる。`docv.yaml` へのリンクは、現在の設定のページに向ける。HTML は clone したリポジトリで見るので、ほかのファイル（コード、管理外のファイルなど）はエディタで開けばよく、リンクにせず文字だけを出す
- 本文の中の http:// と https:// で始まる URL は、`[文字](URL)` の形で書いていなくてもリンクにする。URL は、空白、`<`、`>`、ASCII でない文字の前で終わり、末尾の句読点と、対になっていない `)` は含めない。日本語の文と続けて書いても、後ろの文を URL に含めないため。リンク、画像、コードの中の URL は変えない
- 画像は、元のファイルを出力先から辿れる相対パスで読む
- 表のセルの中のインラインコードは、折り返さない。コマンドやパスが途中で切れないようにするため

---

## 2. README のページ

- ルートの `README.md` を、`README.html` のページにする。`README.md` がないか、`ignore` に当てはまるときは作らない
- `README.md` の h1 をページの h1 にし、本文の見出しは h2 から始まるように段を付け直す。見出しには、GitHub と同じ形のアンカーを付ける
- `README.md` は管理外のままにする。check と fix はかけず、検索の索引にも入れない
- README のページは JPG にしない。Markdown なので、GitHub でそのまま見られる

---

## 3. Slot のページ

- Slot は 1 つずつ独立したページ（`<まとまり>/<Slot>.html`）にする。`index.html`（プロジェクト概要）には、まとまりの見出しの下に、[Slot](slot.md) のページの「一覧」の章の順で、すべての Slot のカードを横に並べる。画面の幅に収まらなければ折り返す。紙面を縦に使いすぎず、画像にしてもすべてのカードが写るため。置いていない Slot のカードは、グレーにしてリンクにしない。どのミッションのドキュメントがないかを見せるため。カードの幅は固定し、画面の幅に合わせない。幅は、いちばん長い Slot の名前（7 文字）が折り返さない大きさ
- Slot のカードと、Slot のページの見出しには、Slot ごとのアイコンを付ける。アイコンは、docv が Slot ごとに持つ線画の SVG で、外部の素材を使わない
- Slot のページには、Slot の名前の見出しを出す。Slot のミッションは HTML には出さない。ミッションは、AI Agent がどの Slot に書くかを決める手がかりにする
- 折りたたみは使わない。`details` も、Markdown の中の `<details>` も、開いて出す。画像にしても、すべての中身が読めるようにするため
- 開閉するのは、OS ごとの手順のタブだけ。手順の中身が 1 つならタブにせず、複数なら書いた順にタブを並べる。JPG では、すべての OS の手順を並べて写す
- 分けたサービス仕様とシステム仕様は、ページを 1 つずつ `サービス/サービス仕様/<h1>.html` と `システム/システム仕様/<h1>.html` にする。Slot の名前の見出しの下に、すべてのページへのリンクを `order` の順にタブとして並べ、開いているページのタブに印を付ける。カードは、先頭のページを開く
- 用語集は、まとまりごとに `name` を h2 にし、`items` を「日本語 | 英語 | 意味」の表にする
- 見た目に凝らない。見出し、段落、箇条書き、表だけで出す
- ディレクトリは、1 つの表に 1 段だけを「名前 | 説明」で出し、入れ子は表を分けて出す。いちばん上の段の表を先に置き、下の段を持つディレクトリごとに、そのパスの h2 と、その下の 1 段の表を後ろに並べる。並びは、親の次にその子の順。下の段を持つディレクトリの名前は、その表へのページ内リンクにする。表の名前はコードの書式にし、h2 のパスはコードの書式にしない。名前の列の幅は、表どうしで揃える。入れ子を折りたたみで見せないのは、画像にしても読めるようにするため。`entries` に書いていない途中のディレクトリは、説明なしで出す
- 見出しは、ページの先頭の h1（Slot の名前）が 1 つだけで、その下に h2 を並べる。段は飛ばさない（h1 の次に h3 や h4 を置かない）
  - Markdown（md の Slot、`appendix_markdown`、`details`、手順の中身）の見出しは、置く場所に合わせて段を付け直す。md の Slot と `appendix_markdown` は h2 から、`details` と手順の中身は h3 から
- 手順（インストール、環境構築）は、「手順」の h2 の下に番号付きで並べる
- 開発コマンドは、順番のない項目なので番号を付けない。先頭に目次（項目へのページ内リンク）を置き、各項目を h2 で始める
- YAML の Slot の `appendix_markdown` は、スキーマで決めた項目のあとに続けて出す
- md の Slot の見出しには、Free ファイルのページと同じく、GitHub と同じ形のアンカーを付ける。`[docv init](#docv-init)` のようなページ内リンクが HTML でも GitHub でも飛べる
- md の Slot のページは JPG にしない。md は GitHub でそのままプレビューできるため

## 4. ADR のページ

- `ADR.html` に、`group` ごとに h2 を置き、決定のつながりを、過去から未来へ左から右に箱と矢印で並べる。打ち消された決定の箱は、破線で薄く出す
- 箱の幅はそろえ、題は箱の中で折り返す。1 列に並びきらないときは、その列を横にスクロールする
- 箱は決定のカードで、クリックすると決定 1 つのページ（`ADR/<group>/<title>.html`）を開く。決定 1 つを 1 ページにする
- 決定のページには、題を h1 にし、本文を出す。本文の見出しは h2 から始まるように段を付け直す。id と日付は出さない
- ADR のページは JPG にしない。ADR は Markdown なので、GitHub でそのまま見られる
- 決定のページの下に、前後の決定をカードで出す。打ち消した過去の決定は ← を付けて左に、この決定を打ち消した新しい決定は → を付けて右に置く。新しい決定へのつながりは、生成するときに `supersedes` を逆にたどって組み立てる
- カーソルキーの ← と → で、前後の決定のページに移れる。前後に決定が複数あるときは、先頭のカードのページに移る

```
言語
+-----------+   +-------------+
| Go にする | → | Rust にする |
+-----------+   +-------------+
+--------------+
| React にする |
+--------------+
```

## 5. 現在の設定のページ

`docv build` は、HTML の「現在の設定」のページに、`docv.yaml` のすべての項目と今の値を 1 つの表で並べる。何を設定でき、どれが効いているかを、スキーマを読まずに見るためのページ。

- 項目は、`dir.html` のように、キーを `.` でつないだ名前で出す。並びは、スキーマの順
- 書いていない項目は、既定の値で出す。値のない項目は `-` を出す
- 配列の項目は、要素を箇条書きにする
- 選ぶ項目（true か false、allow か deny など）は、候補を横に並べ、選んでいる候補に色を付ける
- 表の後に、textlint の検査項目と非検査項目（[設定ファイル](config.md) のページの「textlint」の章）を、それぞれ表で並べる
- Slot ファイルや Free ファイルから `docv.yaml` へのリンクは、HTML ではこのページに向ける

## 6. 毎回同じ出力にする決まり

- 生成日時、実行したマシンのパス、乱数を出力に入れない
- 並び順を固定する。Slot は規格の順（分けたサービス仕様とシステム仕様のページは `order` とパスの順）、Free ファイルはディレクトリのツリーの順、Slot の中の項目は書いた順、ADR は日付と id の順。検索の索引は、Slot ファイル、ADR、Free ファイルの順
- 入力（管理対象のファイル、`README.md`、Slot、ADR、`docv.yaml`、docv の版）が同じなら、HTML とインデックスはバイト単位で同じになる
- JPG は、同じマシン・同じ Chrome・同じフォントなら同じになる。違うマシンで同じにすることはしない。チームで JPG を共有するなら、GitHub Actions などの決まった環境で作る

---

## 7. JPG

- `dir.image` を書いたときだけ、build の最後に作る。`--no-image` を付けると作らない
- Slot のページを 1 枚ずつ、`dir.image` に `<まとまり>/<Slot>.jpg` の名前で置く
- 幅は 1280 CSS ピクセル、画質は 80。印刷の表示で、ページ全体を 1 枚に写す
- Chrome は、環境変数 DOCV_CHROME、OS ごとの標準のインストール先、PATH にある chrome と chromium の順に探す。見つからなければ error で終わる

---

## 8. インデックス

`dir.index` を書いたときだけ、build が `docv-index.md` を書く。GitHub でリポジトリを開いた人が、clone しなくても Slot ファイルを読めるようにするためのリンク集。README からリンクして使う。

- Slot を、HTML のプロジェクト概要と同じく、まとまりごとに規格の順で、リンクの箇条書きにして並べる。分けたサービス仕様とシステム仕様は、Slot の名前の下に、ページを `order` の順に入れ子で並べる。置いていない Slot は出さない
- md の Slot は、元のファイルへリンクする。GitHub で Markdown のまま読めるため。ファイルがシンボリックリンクなら、ルートの中にある先のファイルへリンクする。GitHub は、シンボリックリンクを開いても先の中身を出さないため
- YAML の Slot は、`dir.image` を書いていれば JPG へリンクし、書いていなければ出さない。JPG へリンクするかは `dir.image` を書いたかで決め、`--no-image` を付けても同じインデックスにする
- Free ファイルと ADR は、それぞれの章に、置いているディレクトリへのリンクだけを出す。どちらも詳細やプロジェクト固有の情報で、知りたくなった人は clone すると考えるため。検索とタグでの絞り込みはプロジェクト詳細のページで、ADR のつながりの図は ADR のページで見られると、`docv open` と、そのページの `dir.html` の中のパスで案内する
- リンクは、`docv-index.md` の場所からの相対パスで、`[名前](<パス>)` の形で書く。パスに空白や日本語が入っても、GitHub で辿れるようにするため
- 1 行目に、docv が作ったことを示すコメントを書く。build は、このコメントで始まらない `docv-index.md` を書き換えない（[コマンド](cli.md) のページの「ファイルを書くコマンド」の章）
- インデックスが古いままかは、check で確かめない。Slot を変えたら build で作り直す
- エイリアス（シンボリックリンク）やコピーを並べたディレクトリは作らない。GitHub はシンボリックリンクの先を出さず、コピーは同じ中身を 2 か所で持つことになり、md の中の相対リンクも壊れるため
