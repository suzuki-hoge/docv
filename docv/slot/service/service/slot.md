# Slot

どのプロジェクトにも要るドキュメントを、docv が決めたミッションと形で書くファイルの規格。

---

## 1. 置き場所と書き方

- Slot ファイルは、`docv.yaml` の `dir.document_root`（既定は `docv`）の下の `slot/` に、`<まとまり>/<Slot>.md` の名前で置く。まとまりのディレクトリは `service`（サービス）、`system`（システム）、`guide`（開発者向けガイド）、`operation`（運用）。Free ファイルは `free/` に置く（[設定ファイル](config.md) のページの「配置」の章）
- Slot ファイルは、すべて Markdown（`.md`）で書き、そのまま HTML に出す
- サービス仕様、システム仕様、開発コマンド、アーキテクチャ、設計・実装、テスト方針、インフラと環境だけは、ページに分けて `<まとまり>/<Slot>/` に置ける（「ページ分け」の章）
- ADR と PDR は、`slot/` ではなく、`document_root` の下の `adr/` と `pdr/` に置く
- `slot/` の中でも、除外に当たるファイル（[設定ファイル](config.md) のページの「docv が読むファイル」の章）と、名前がドットで始まるファイルとディレクトリ（`.DS_Store` など）は読まない。画像（[Free](free.md) のページの「画像」の章）は、Slot の隣に `{Slot の名前}_{画像の名前}.{拡張子}` の名前で置ける。ページに分けた Slot のページの隣には、`{ページの名前}_{画像の名前}.{拡張子}` で置ける。それ以外で Slot の名前でないファイルは、check が slot-unknown の error にする
- Slot を置くかどうかは任意。プロジェクトに当てはまらない Slot は作らない（例: 利用者の手元に入れるものがなければ、インストールの Slot はいらない）
- Slot のミッションに当たる詳しいことも、Slot の中に書く。Free ファイルへのリンクで済ませない
- Slot の中のリンクは、ほかの Markdown と同じく、ファイルの場所からの相対パスで書く
- `docv gen <slot>` で、Slot ファイルを決まったパスに作れる（`docv list` で一覧とミッションを出す）

## 2. 一覧

HTML には、この表の順に、まとまりごとに並べる。

| ファイル                      | Slot           | まとまり         | ミッション                                                                                     |
| ----------------------------- | -------------- | ---------------- | ---------------------------------------------------------------------------------------------- |
| `service/overview.md`         | サービス概要   | サービス         | 利用者に向けた、これが何で、誰の何を解決し、何ができるかの説明                                 |
| `service/service.md`          | サービス仕様   | サービス         | 外から見た機能と、それぞれの振る舞いと決まり                                                   |

| `service/manual.md`           | 利用マニュアル | サービス         | 利用者の使い方（CLI のコマンド、GUI の操作など）                                               |
| `service/words.md`            | 用語集         | サービス         | このプロジェクトの言葉の意味                                                                   |
| `system/system-overview.md`   | システム概要   | システム         | 開発者に向けた、システムを作る部品と、そのつながりの全体像                                     |
| `system/system.md`            | システム仕様   | システム         | 部品ごとの振る舞いと、部品の間の流れ                                                           |
| `system/stack.md`             | 技術スタック   | システム         | 利用している外部サービス、言語、ライブラリなどの名前と用途                                     |
| `system/api.md`               | API 仕様書     | システム         | API の一覧と、それぞれが受け取るものと返すもの                                                 |
| `system/db.md`                | DB 仕様書      | システム         | 保存しているデータと、その保存先と形                                                           |
| `guide/setup.md`              | 環境構築       | 開発者向けガイド | 開発を始めるのに用意するものと、実行するコマンド                                               |
| `guide/develop.md`            | 開発コマンド   | 開発者向けガイド | テストやビルドなど、開発者が実行するコマンド                                                   |
| `guide/architecture.md`       | アーキテクチャ | 開発者向けガイド | システム全体で採る方式と決まり（部品の分け方、通信の方式、非同期処理の実現方法など）           |
| `guide/design.md`             | 設計・実装     | 開発者向けガイド | コードを書くときに従う決まり（フレームワークの使い方、ディレクトリやコーディングの決まりなど） |
| `guide/testing.md`            | テスト方針     | 開発者向けガイド | テストの範囲と方法（自動テストの範囲、E2E テスト、手動テストについてなど）                     |
| `guide/env.md`                | 環境変数       | 開発者向けガイド | システムを動かすのに要る環境変数と、それぞれを設定している場所                                 |

| `operation/infrastructure.md` | インフラと環境 | 運用             | 環境（本番、ステージング、開発など）の一覧と、それぞれの用途                                   |
| `operation/deploy.md`         | デプロイ       | 運用             | 作ったものを環境に反映する手順                                                                 |
| `operation/release.md`        | リリース       | 運用             | 版の決め方と、利用者への届け方                                                                 |
| `operation/cost.md`           | 費用           | 運用             | かかっている費用と、費用を理由にやっていないこと                                               |

- Slot の名前に近いパスで置くと、check が slot-unknown で正しいパスを示す。たとえば、まとまりのディレクトリが違う `words.md`、番号を付けた `service/03-words.md`、拡張子が違う `service/service.txt`
- 利用マニュアル（manual）と開発コマンド（develop）を分けるのは、使う人と目的が違うため。利用マニュアルは、リポジトリが CLI や GUI のときの、利用者向けの使い方
- サービス概要には、これは何で、何に使えるかを、利用者に向けて書く。サービス仕様には、外から見た機能と、それぞれがどう振る舞うかを詳しく書く。実装をそっくり差し替えても変わらないことが、サービス仕様になる
- システム概要には、どんな部品からなり、どうつながっているかを、開発者に向けて図で書く。システム仕様には、部品ごとの振る舞いと、部品の間の流れを詳しく書く。部品を作る言語やライブラリは、技術スタックに書く
- アーキテクチャには、部品の分け方とつなぎ方など、システム全体で採る方式と、部品をまたいで守る決まりを書く。どんな部品がありどうつながっているかはシステム概要に、使っている製品やライブラリの名前は技術スタックに書く。たとえば、重い処理をキューに積んでワーカーで非同期に行う方式は、アーキテクチャに書く。そのキューとワーカーはシステム概要に、注文の確定がキューを通ってワーカーに届く流れはシステム仕様に、キューの製品の名前は技術スタックに書く
- 設計・実装には、コードを書くときに従う決まりを書く。今のコードの作りは書かない。コードを読んでも、守るべき決まりか、たまたまそうなっているかは分からないため。ディレクトリの決まりも、ここに書く
- テスト方針には、何をどのテストで確かめるかを書く。テストを実行するコマンドは、開発コマンドに書く
- インフラと環境には、ある環境だけでなく、ない環境も書く（例: ステージングと本番があり、開発サーバーはない）
- デプロイは環境に反映すること、リリースは利用者に届けることで、どちらかしかないプロジェクトもある（例: サーバーを持たない CLI はリリースだけ）

## 3. 書き方

- 中身の形は、check では確かめない
- YAML front matter には `mission` だけを書き、`docv list` のミッションと同じ文にする。ミッションは docv が決めるもので、プロジェクトでは変えない。ないか違えば、check が slot-mission の error にする。docv の版を上げてミッションが変わったときも、check で気づいて直す。ファイルを開けば、何を書く Slot かが分かるようにするため
- `mission` がないか違っても、HTML には本文を出す
- `docv gen` は、雛形のある Slot には雛形を作る。ほかの Slot には、YAML front matter の `mission` だけを書いたファイルを作り、中身の形は自由だと表示する
- 雛形にも `mission` を書いてある。作った雛形はプロジェクトのもので、列や文を足すのは自由。docv の版を上げても書き換えない
- 雛形の形から外れていないかは、check ではなく、`docv review-guide` のレビューで見る

| Slot                   | 雛形の形                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 用語集                 | まとまりごとの h2 の下に、用語、英語、意味の表を置く                                                                                            |
| 技術スタック           | 層ごとの h2 の下に、名前と用途の表を置く                                                                                                        |
| 環境変数               | キー、説明、ローカル環境、運用環境の表を置く。秘密の値のキーには 🔒 を付ける                                                                    |
| 費用                   | 「かかっている費用」と「費用を理由にやっていないこと」の h2 の下に、説明と月額の表を置く。説明は項目の名前から書き出し、参考の URL は末尾に置く |
| インストール、環境構築 | 「前提とされるもの」と「手順」の h2 を置く                                                                                                      |
| 開発コマンド           | 冒頭に、することとコマンドの表を置く。続けて、することごとの h2 の下に、実行の例、オプションの表、行われることの畳んだ箇条書きを置く            |
| Doc ガイド             | docv が勧めるガイドライン                                                                                                                       |

## 4. ページ分け

サービス仕様、システム仕様、開発コマンド、アーキテクチャ、設計・実装、テスト方針、インフラと環境は、ページに分けられる。1 つのページが長くならないようにするため。読む人ごとに仕様が分かれるサービス（利用者向けの機能と管理者向けの機能など）、部品の多いシステム（画面、サーバ、バッチなど）、部品ごとに開発のコマンドや決まりや環境が違うプロジェクトで分ける。

| Slot           | 1 つのファイル                | ページのディレクトリ        |
| -------------- | ----------------------------- | --------------------------- |
| サービス仕様   | `service/service.md`          | `service/service/`          |
| システム仕様   | `system/system.md`            | `system/system/`            |
| 開発コマンド   | `guide/develop.md`            | `guide/develop/`            |
| アーキテクチャ | `guide/architecture.md`       | `guide/architecture/`       |
| 設計・実装     | `guide/design.md`             | `guide/design/`             |
| テスト方針     | `guide/testing.md`            | `guide/testing/`            |
| インフラと環境 | `operation/infrastructure.md` | `operation/infrastructure/` |

- 分けるときは、1 つのファイルの代わりに、ページのディレクトリの直下に 1 ページ 1 つの Markdown で置く。ファイル名は自由。両方に置くと check の error になる
- どのページにも、並びの `order`（整数）とページの名前を書く。ページは `order` の順に並べる。`order` もページの名前も、同じ Slot のページどうしで重ねない。ほかの Slot のページとは比べない
- 分けないときは、今までどおり 1 つのファイルに書く
- `docv gen` は、1 つのファイルを作り、分けるときの置き場所も表示する。ページがあるときは、1 つのファイルを作らずに error で終わる。ページは手で置く

ページは、YAML front matter に `order` と `mission` を書く。`mission` は、分けないときと同じく、その Slot のミッションと同じ文にする。本文の h1 が、ページの名前になる。

```markdown
---
order: 2
mission: 外から見た機能と、それぞれの振る舞いと決まり
---

# 管理者向け機能
```

## 5. check

| ID           | 内容                                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| slot-unknown | `slot/` に、Slot の名前でも画像でもないファイルがある                                                                                     |
|              | YAML の Slot（`service/words.yaml` など、Slot の名前の `.yaml`）がある。`docv gen <slot> --print` の雛形を見て、md に書き直すよう案内する |
| slot-invalid | 分けたページの形に合わない。`order` やページの名前（h1）がない、知らない項目、同じ Slot のページどうしの重なり                            |
|              | YAML front matter に、知らない項目がある。閉じる `---` がない                                                                             |
|              | 同じ Slot が、1 つのファイル（`service/service.md` など）と、ページのディレクトリ（`service/service/` など）の両方にある                  |
| slot-mission | YAML front matter に `mission` がないか、`docv list` のミッションと違う                                                                   |

- Slot には、YAML front matter のほかは、Free ファイルと同じ検査（[Free](free.md) のページの「check のルール」の章）をかける
- `slot/` の中の画像には、Free ファイルの画像と同じ検査（image-owner）をかける
