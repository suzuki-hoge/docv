# Slot

どのプロジェクトにも要るドキュメントを、docv が決めたミッションと形で書くファイルの規格。Slot を置く理由は [概要](desc.md) のページに、HTML の全体は [ビジュアライズ](html.md) のページに書く。

---

## 1. 置き場所と書き方

- Slot ファイルは、`docv.yaml` の `dir.document_root`（既定は `docv`）の下の `slot/` に、`<まとまり>/<Slot>.<拡張子>` の名前で置く。まとまりのディレクトリは `service`（サービス）、`system`（システム）、`guide`（開発者向けガイド）、`operation`（運用）。Free ファイルは `free/` に置く（[設定ファイル](config.md) のページの「配置」の章）
- 拡張子は Slot ごとに決まる。YAML の Slot は決まった項目で書き、md の Slot は中身の形を決めず、そのまま HTML に出す
- サービス仕様、システム仕様、開発コマンド、アーキテクチャ、設計・実装、テスト方針、インフラと環境だけは、ページに分けて `<まとまり>/<Slot>/` に置ける（「ページ分け」の章）
- ADR と PDR は、`slot/` ではなく、`document_root` の下の `adr/` と `pdr/` に置く（[ADR](adr.md) と [PDR](pdr.md) のページ）
- `slot/` の中でも、除外に当たるファイル（[設定ファイル](config.md) のページの「docv が読むファイル」の章）と、名前がドットで始まるファイルとディレクトリ（`.DS_Store` など）は読まない。画像（[Free](free.md) のページの「画像」の章）は、Slot の隣に `{Slot の名前}_{画像の名前}.{拡張子}` の名前で置ける。ページに分けた Slot のページの隣には、`{ページの名前}_{画像の名前}.{拡張子}` で置ける。それ以外で Slot の名前でないファイルは、check が slot-unknown の error にする
- Slot を置くかどうかは任意。プロジェクトに当てはまらない Slot は作らない（例: 利用者の手元に入れるものがなければ、インストールの Slot はいらない）
- Slot のミッションに当たる詳しいことも、Slot の中に書く。Free ファイルへのリンクで済ませない
- ファイルの中のパスは、すべてルートからの相対パスで書く。md の Slot の中のリンクは、ほかの Markdown と同じく、ファイルの場所からの相対パスで書く
- YAML の文字列の項目には Markdown を書ける
- `docv slot gen <slot>` で、Slot ファイルを決まったパスに作れる。YAML の Slot には項目のサンプルを書き、md の Slot には YAML front matter の `mission` だけを書く（`docv slot list` で一覧とミッションを出す）

- Slot の名前に近いパスで置くと、check が slot-unknown で正しいパスを示す。たとえば、まとまりのディレクトリが違う `words.yaml`、番号を付けた `service/03-words.yaml`、拡張子が違う `service/service.yaml`
- 利用マニュアル（manual）と開発コマンド（develop）を分けるのは、使う人と目的が違うため。利用マニュアルは、リポジトリが CLI や GUI のときの、利用者向けの使い方
- サービス概要には、これは何で、何に使えるかを、利用者に向けて書く。サービス仕様には、外から見た機能と、それぞれがどう振る舞うかを詳しく書く。実装をそっくり差し替えても変わらないことが、サービス仕様になる
- システム概要には、どんな部品からなり、どうつながっているかを、開発者に向けて図で書く。システム仕様には、部品ごとの振る舞いと、部品の間の流れを詳しく書く。部品を作る言語やライブラリは、技術スタックに書く
- アーキテクチャには、部品の分け方とつなぎ方など、システム全体で採る方式と、部品をまたいで守る決まりを書く。どんな部品がありどうつながっているかはシステム概要に、使っている製品やライブラリの名前は技術スタックに書く。たとえば、重い処理をキューに積んでワーカーで非同期に行う方式は、アーキテクチャに書く。そのキューとワーカーはシステム概要に、注文の確定がキューを通ってワーカーに届く流れはシステム仕様に、キューの製品の名前は技術スタックに書く
- 設計・実装には、コードを書くときに従う決まりを書く。今のコードの作りは書かない。コードを読んでも、守るべき決まりか、たまたまそうなっているかは分からないため。ディレクトリの決まりも、ここに書く
- テスト方針には、何をどのテストで確かめるかを書く。テストを実行するコマンドは、開発コマンドに書く
- インフラと環境には、ある環境だけでなく、ない環境も書く（例: ステージングと本番があり、開発サーバーはない）
- デプロイは環境に反映すること、リリースは利用者に届けることで、どちらかしかないプロジェクトもある（例: サーバーを持たない CLI はリリースだけ）。どちらも、環境ごとの違い、承認、切り戻しなど、手順の形に収まらないことを書くので md にする

## 3. YAML の Slot の項目

- 項目の形と意味は、Slot ごとのスキーマ（JSON Schema）で決める。`docv slot schema <slot>` で出す。元のファイルは `assets/schema/<ID>.schema.json` で、`docv/free/schema/` に写しを置く
- `docv slot gen` は、YAML の Slot の 1 行目に、yaml-language-server の書式でスキーマの URL を書く。URL は、実行した CLI の版のタグの `assets/schema/` を指す。エディタで項目の補完と検証が効く。URL の版は `docv.yaml` の `docv_version` と揃える（[設定ファイル](config.md) の「docv の版」の章）
- 名前が `_markdown` で終わる項目は Markdown。値は、1 行でも必ず `|` のブロックで書く。`|-`、`|+`、字下げの数を付けた `|2` などは使わない。それ以外の文字列の項目は、Markdown として扱わず、1 行で書く
- Markdown の項目の中のリンクは、ルートからの相対パスで書く
- どの YAML の Slot にも、`appendix_markdown` を書ける。項目に収まらない補足を書く

```yaml
groups:
  - name: ファイルの種類
    items:
      - en: Slot
        desc_markdown: |
          どのプロジェクトにも要るドキュメントを書くファイル。`docv/slot/` に置く
```

## 4. md の Slot

- 中身の形は決めない
- YAML front matter には `mission` だけを書き、`docv slot list` のミッションと同じ文にする。ミッションは docv が決めるもので、プロジェクトでは変えない。ないか違えば、check が slot-mission の error にする。docv の版を上げてミッションが変わったときも、check で気づいて直す。ファイルを開けば、何を書く Slot かが分かるようにするため
- `mission` がないか違っても、HTML には本文を出す
- `docv slot gen` は、YAML front matter の `mission` だけを書いたファイルを作り、中身の形は自由だと表示する。Doc ガイド（`guide/doc-guide.md`）だけは、docv が勧めるガイドラインを書いた雛形を作る。雛形にも `mission` を書いてある。作った雛形はプロジェクトのもので、自由に直してよい。docv の版を上げても書き換えない

## 5. ページ分け

サービス仕様、システム仕様、開発コマンド、アーキテクチャ、設計・実装、テスト方針、インフラと環境は、ページに分けられる。1 つのページが長くならないようにするため。読む人ごとに仕様が分かれるサービス（利用者向けの機能と管理者向けの機能など）、部品の多いシステム（画面、サーバ、バッチなど）、部品ごとに開発のコマンドや決まりや環境が違うプロジェクトで分ける。

| Slot           | 1 つのファイル                | ページのディレクトリ        |
| -------------- | ----------------------------- | --------------------------- |
| サービス仕様   | `service/service.md`          | `service/service/`          |
| システム仕様   | `system/system.md`            | `system/system/`            |
| 開発コマンド   | `guide/develop.yaml`          | `guide/develop/`            |
| アーキテクチャ | `guide/architecture.md`       | `guide/architecture/`       |
| 設計・実装     | `guide/design.md`             | `guide/design/`             |
| テスト方針     | `guide/testing.md`            | `guide/testing/`            |
| インフラと環境 | `operation/infrastructure.md` | `operation/infrastructure/` |

- 分けるときは、1 つのファイルの代わりに、ページのディレクトリの直下に 1 ページ 1 つのファイルで置く。拡張子は、分けないときと同じ。ファイル名は自由。両方に置くと check の error になる
- どのページにも、並びの `order`（整数）とページの名前を書く。ページは `order` の順に並べる。`order` もページの名前も、同じ Slot のページどうしで重ねない。ほかの Slot のページとは比べない
- 分けないときは、今までどおり 1 つのファイルに書く
- `docv slot gen` は、1 つのファイルを作り、分けるときの置き場所も表示する。ページがあるときは、1 つのファイルを作らずに error で終わる。ページは手で置く

md のページ（開発コマンドのほかの Slot のページ）は、YAML front matter に `order` と `mission` を書く。`mission` は、分けないときと同じく、その Slot のミッションと同じ文にする。本文の h1 が、ページの名前になる。

```markdown
---
order: 2
mission: 外から見た機能と、それぞれの振る舞いと決まり
---

# 管理者向け機能
```

YAML のページ（開発コマンド）は、分けないときの項目に、`order` と、ページの名前の `title` を足す。スキーマは分けないときと同じで、`order` と `title` は、どちらも書くか、どちらも書かない。分けないときのファイルには、どちらも書かない。

```yaml
order: 1
title: Web 画面
steps:
  - id: test
    name: テストを実行する
    items:
      body_markdown: |
        npm test
```

## 6. check

| ID                  | 内容                                                                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| slot-unknown        | `slot/` に、Slot の名前でも画像でもないファイルがある                                                                      |
| slot-invalid        | YAML の Slot の形に合わない。知らない項目、手順の `id` や `os` の重なり、`os` のない `item`、`ja` も `en` もない用語も含む |
|                     | 分けたページの形に合わない。`order` やページの名前（h1 か `title`）がない、知らない項目、同じ Slot のページどうしの重なり  |
|                     | md の Slot の YAML front matter に、知らない項目がある。閉じる `---` がない                                                |
|                     | 同じ Slot が、1 つのファイル（`service/service.md` など）と、ページのディレクトリ（`service/service/` など）の両方にある   |
|                     | 分けないときの開発コマンド（`guide/develop.yaml`）に、`order` か `title` がある                                            |
| slot-mission        | md の Slot の YAML front matter に `mission` がないか、`docv slot list` のミッションと違う                                 |
| slot-path-missing   | パスの先がない                                                                                                             |
| slot-markdown-style | `_markdown` で終わる項目を、`\|` のブロックで書いていない                                                                  |
| slot-text-multiline | `_markdown` で終わらない文字列の項目が、複数行になっている                                                                 |

- md の Slot には、YAML front matter のほかは、Free ファイルと同じ検査（[Free](free.md) のページの「check のルール」の章）をかける
- `slot/` の中の画像には、Free ファイルの画像と同じ検査（image-owner）をかける
- YAML の Slot の Markdown の項目には、リンク、書式の規則、整形、textlint の検査をかける。見出しの検査はかけない。項目の中に h1 はなく、HTML では見出しの段を付け直すため。指摘の行番号は、YAML の行番号で出す
