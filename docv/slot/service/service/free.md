# Free

docv が管理する Free ファイル（`docv.yaml` の `dir.document_root` の下の `free/` にある Markdown）のルールと、ドキュメントで使う画像のルール。何をどう書くかはガイドライン（Slot の Doc ガイド、`guide/doc-guide.md`）で、プロジェクトが決める。Slot のルールは [Slot](slot.md)、ADR と PDR のルールは [ADR](adr.md) と [PDR](pdr.md)、`docv.yaml` は [設定ファイル](config.md) のページに書く。

---

## 1. YAML front matter

| key       | 必須 | 中身                                                 |
| --------- | ---- | ---------------------------------------------------- |
| `mission` | 必須 | ミッション。このファイルを読むと何が分かるか（1 文） |
| `tags`    | 任意 | タグの配列（「タグ」の章）                           |

```yaml
---
mission: 注文を確定するタイミングと、失敗したときの扱い
tags: [仕様, 注文]
---
```

- `mission` は 1 行で書く
- ファイルごとの設定は、すべて YAML front matter に書き、`docv.yaml` には書かない。ファイルを動かしても設定がずれず、AI Agent はファイルを読むだけで、そのファイルの扱いが分かる
- docv が知らない key は、そのまま残し、check もしない。作成者の記録（`created` / `updated` など）のように、プロジェクトが決めた key を書いてよい
- HTML は、`mission` をファイルの説明として表示する

---

## 2. タグ

- Free ファイルの分類は、YAML front matter の `tags` に書くタグで行う。1 つのファイルにいくつでも付けられる
- docv はタグの意味を決めない。どんなタグを使うかは、プロジェクトが決める
- 使うタグは、すべて `docv.yaml` の `tags` に書く。`tags` にないタグを付けると、check が error にする
- `tags` には、タグごとに名前（`name`）と色（`color`）を書く。色は HTML でタグを見分けるためのもので、blue、green、yellow、red、purple、orange、teal、pink から選ぶ

```yaml
tags:
  - name: 仕様
    color: blue
  - name: 計画
    color: green
```

## 3. check のルール

`docv check` が Free ファイルで確かめるルール。`docv.yaml` で使うと決めたときだけ確かめるもの（太字などの書式の規則、整形、textlint）は [設定ファイル](config.md) のページに書く。

### YAML front matter

| ID                  | 内容                                                       |
| ------------------- | ---------------------------------------------------------- |
| frontmatter-invalid | YAML front matter が読めない。`mission`、`tags` の型が違う |
| mission-missing     | `mission` がない                                           |
| mission-multiline   | `mission` が複数行                                         |
| tag-unknown         | `docv.yaml` の `tags` にないタグがある                     |

### 構造とリンク

| ID             | 内容                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| title-count    | h1 が 1 つでない                                                         |
| heading-number | 章番号で始まる h2 があるのに、h2 が `1. ` から順に章番号で始まっていない |
| link-broken    | ルートの中を指す相対リンクの先にファイルがない                           |
| link-anchor    | リンクのアンカー（`#` 以降）が指す見出しが、リンク先の Markdown にない   |

- 章番号は、h2 のどれかが `1. ` のような章番号で始まっているファイルでだけ確かめる。章番号を使わないファイルでは確かめない
- アンカーは、HTML の見出しと同じく GitHub と同じ形で作る。同じ見出しが続けば `-1`、`-2` を付ける。`#` だけのページ内リンクは、そのファイルの見出しと比べる。Markdown でないファイルへのリンクのアンカーは確かめない

## 4. 画像

Free ファイル、Slot ファイル、ADR、PDR で使う画像の置き場所と名前。

- 画像は、使うファイルと同じディレクトリに置く。共通の画像のディレクトリは作らない
- 名前は `{使うファイルの名前}_{画像の名前}.{拡張子}` にする。使うファイルの名前は、拡張子を除いた名前。たとえば、`order.md` で使う流れの図は `order_flow.svg`。名前の順に並べると、画像が使うファイルの隣に来る
- 複数のページで使う画像は、主になるページの隣に置き、ほかのページからはそのパスを参照する
- ADR と PDR は、それぞれのディレクトリ（`adr/`、`pdr/`）の中の画像だけを参照できる（[ADR](adr.md) のページの「check」の章）。それ単体で完結することに価値があり、最新のドキュメントの内容に過去の決定が左右されないようにするため
- 画像として扱うのは、拡張子が png、jpg、jpeg、gif、svg、webp のファイル

| ID          | 内容                                                                                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| image-owner | `free/`、`slot/`、`adr/`、`pdr/` の下の画像に、持ち主がない。持ち主は、同じディレクトリにある、名前（拡張子を除く）が画像の名前の `_` より前と同じ Markdown か YAML のファイル |

- 画像の名前に `_` がいくつかあるときは、どの `_` で区切っても、持ち主が見つかればよい。使うファイルの名前に `_` が入っていても、名前の付け方を変えずに済むため
