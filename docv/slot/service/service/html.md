# ビジュアライズ

`docv build` が作る HTML とインデックスの作り。`docv diff-open` が作る HTML は、最後の章に書く。HTML は `dir.output` の下の `html/` に、インデックスは `document_root` の直下の `README.md` に書く。以下、出力先は `html/` を指す。

---

## 1. HTML の作り

- CSS と JS は、出力先の直下の `docv.css` と `docv.js` に書き、各ページから相対パスで読む。ページの中には書かない。出力先をコミットするリポジトリで、CSS や JS を変えたときの差分を 1 ファイルに収めるため。外部の CDN は使わない。file:// で開いても、ホスティングしても見られる。画像は元のファイルを読むので、ホスティングするときは、画像を置いた `document_root` も含めて公開する
- JS は、決定のページのカーソルキーでの移動、Free のページのタグのトグル、検索のページ、元のファイルのパスのコピー、diff-open の行数の吹き出しにだけ使う。JS が動かなくても、すべての中身は読め、リンクから辿れる。コピーのボタンは JS が動くときだけ出す。ページに分けた Slot のタブは、ページへのリンクにする
- 出力するファイルとディレクトリの名前からは、空白を除く。Slot、ページに分けた Slot、ADR、PDR、Free ファイルのページのどれも同じ。たとえば、Doc ガイドのページは `開発者向けガイド/Docガイド.html`、題が「Go にする」の決定は `ADR/<group>/Goにする.html` になる。CLI や git で、引用符なしでパスを扱えるようにするため。Free ファイルのページは、元のパスのディレクトリの名前からも空白を除く
- すべてのページの左に、README とトップの 8 ページへのサイドバーを、右に、そのページの h2 と h3 の目次を置く。見出しのないページでは、目次の代わりに同じ幅の空きを置き、ページを移っても本文の位置を変えない。幅の狭い画面では、左のサイドバーを本文の上に置き、項目を折り返して並べる。印刷の表示では、どちらのサイドバーも出さない
- サイドバーには、次の 3 つの段の順に項目を並べ、段の間に横線を引く。項目の名前は、サイドバーの幅で折り返さないように短くする。README は、そのページがあるときだけ出す。ADR と PDR は、決定があるときだけ出す
  - ドキュメント: README、Slot、Free、ADR、PDR
  - docv が作るもの: Index、Review Guide、Config
  - Search
- 左のサイドバーの一番下に、作った docv の版を `Generated by docv <版>` の形で出す。どの版の docv で作ったページかを、見て分かるようにするため
  - docv は docv のリポジトリへ、版はその版のタグのソースへリンクする
- トップの 8 ページは、サイドバーと同じページの名前を h1 にする。ただし ADR の h1 は Architecture Decision Record、PDR の h1 は Product Decision Record で、略さずに書く。サイドバーは幅へ収まるよう略すが、ページでは何の記録かを読んで分かるようにするため
- トップのページの HTML のファイルの名前は、Slot が `index.html`、Free が `プロジェクト詳細.html`、ADR が `ADR.html`、PDR が `PDR.html`。Index、Review Guide、Config、Search は、`インデックス.html`、`レビューガイド.html`、`現在の設定.html`、`検索.html`
- Slot、ADR、PDR、Free ファイルのページの h1 の上に、元のファイルのルートからのパスを小さく出し、横にパスをクリップボードにコピーするボタンを置く。ページを見て編集したくなったときに、元のファイルを見つけられるように。Slot のページでは、同じ行の左に Slot のミッションを出し、パスとボタンを右に寄せる。ミッションは、パスと同じ大きさ、色、字体にする。1 行に収まらなければ、パスを次の行の右に送る
- 検索のページは、Slot ファイル、ADR、PDR、Free ファイルの中身を行ごとに並べた索引を、`docv.js` ではなく検索のページの中に書く。入力した文字列をそのまま含む行を探し、入力欄の下に、ファイルごとにパス、タグ、ヒットした行の前後 2 行を並べる。プレビューの長い行は、折り返さずに横へスクロールする。入力欄は、JS が動くときだけ出す
- フェンスのコードブロックは、フェンスに書いた言語（`yaml` など）に合わせて、build のときに色を付ける。色は HTML の中に埋め込み、JS は使わない。言語がないか、docv が知らない言語なら、色を付けずに出す
- リンクは、README、Free ファイル、Slot ファイル、ADR、PDR のページにだけ、出力先の中の相対パスで張る（ツリー、Slot ファイルや Free ファイルの本文の中のリンク）。file:// で開けば file:// のまま、ホスティングすればその中で辿れる。`docv.yaml` へのリンクは、現在の設定のページに向ける。HTML は clone したリポジトリで見るので、ほかのファイル（コード、管理外のファイルなど）はエディタで開けばよく、リンクにせず文字だけを出す
- 本文の中の http:// と https:// で始まる URL は、`[文字](URL)` の形で書いていなくてもリンクにする。URL は、空白、`<`、`>`、ASCII でない文字の前で終わり、末尾の句読点と、対になっていない `)` は含めない。日本語の文と続けて書いても、後ろの文を URL に含めないため。リンク、画像、コードの中の URL は変えない
- 画像は、元のファイルを出力先から辿れる相対パスで読み、出力先にはコピーしない。出力先をコミットするリポジトリで、同じ画像を 2 か所に持たないため
- 表のセルの中のインラインコードは、折り返さない。コマンドやパスが途中で切れないようにするため
- 同じページの中で、見出しの行が同じ表は、列の幅をそろえる。並んだ表を、1 つの表と同じく縦方向で読めるようにするため
  - 短い列は、その列のどの表のセルも折り返さない幅にし、いちばん長い列が残りの幅を使う
- 段落と箇条書きは、表やコードと同じ右端で折り返す。本文の幅は、ページの本文の幅で抑える
- 表が横にはみ出すときは、ページごと広げず、表の中だけを横にスクロールさせる
- 本文の中のリンクには下線を付け、色だけでリンクを示さない。キーボードで移ったときは、どこにいるかを枠で示す

## 2. README のページ

- ルートの `README.md` を、`README.html` のページにする。`README.md` がないか、`docv_exclude` に当てはまるときは作らない
- `README.md` の h1 をページの h1 にし、本文の見出しは h2 から始まるように段を付け直す。見出しには、GitHub と同じ形のアンカーを付ける
- `README.md` は管理外のままにする。check と fix はかけず、検索の索引にも入れない

---

## 3. Slot のページ

- Slot は 1 つずつ独立したページ（`<まとまり>/<Slot>.html`）にする。`index.html`（Slot）には、まとまりの見出しの下に、[Slot](slot.md) のページの「一覧」の章の順で、すべての Slot のカードを横に並べる。画面の幅に収まらなければ折り返す。紙面を縦に使いすぎず、画像にしてもすべてのカードが写るため。置いていない Slot のカードは、グレーにし、破線の枠と「未作成」の文字を付けて、リンクにしない。どのミッションのドキュメントがないかを、色だけに頼らずに見せるため。ページに分けられる Slot のカードには、「未作成」と同じ位置に、ページの数を `3 tabs` の形で出す。分けていないか、1 ページだけなら `1 tab`。開く前に、ページに分けられる Slot かと、ページの数が分かるようにするため。カードの幅は固定し、画面の幅に合わせない。幅は、いちばん長い Slot の名前（7 文字）が折り返さない大きさ
- Slot のカードと、Slot のページの見出しには、Slot ごとのアイコンを付ける。アイコンは、docv が Slot ごとに持つ線画の SVG で、外部の素材を使わない
- Slot のページには、Slot の名前の見出しを出す。h1 の上の、元のファイルのパスと同じ行に、Slot のミッションを出す（「HTML の作り」の章）。何を書くページかを、人間もページの中で分かるようにするため。出すのは docv が Slot ごとに決めた文で、YAML front matter の `mission` は、check で同じ文だと確かめるので読まない
- Markdown の中の `<details>` は、閉じて出す。詳細は、知りたくなったときに開けば足りるため。印刷の表示では、開いて出す。紙では開けないため
- `<details>` は枠で囲み、見出し（`<summary>`）と中身の間に線を引く。見出しにマウスを乗せたら、カーソルを指の形にする。どこまでが折りたたんだ中身か、どこを押せば開くかを分かるようにするため。開いているときだけ、見出しの背景を左のサイドバーと同じ色にする。開いているかを、印の向きのほかに色でも分かるようにするため
- 開閉するのは、`<details>` だけ
- ページに分けた Slot は、ページを 1 つずつ `<まとまり>/<Slot>/<ページの名前>.html`（`サービス/サービス仕様/管理者向け機能.html` など）にする。ページの名前は、ページの h1。Slot の名前の見出しの下に、すべてのページへのリンクを `order` の順にタブとして並べ、開いているページのタブに印を付ける。タブの下の中身は、分けないときの Slot と同じ形で出す。カードは、先頭のページを開く
- 見た目に凝らない。中身は、見出し、段落、箇条書き、表だけで出す
- 見出しは、ページの先頭の h1（Slot の名前）が 1 つだけで、その下に h2 を並べる。段は飛ばさない（h1 の次に h3 や h4 を置かない）
  - Slot の本文の見出しは、h2 から始まるように段を付け直す
- Slot の見出しには、Free ファイルのページと同じく、GitHub と同じ形のアンカーを付ける。`[docv init](#docv-init)` のようなページ内リンクが HTML でも GitHub でも飛べる

## 4. ADR と PDR のページ

ADR と PDR は、同じ作りのページにする。違うのは、一覧のページ（`ADR.html` と `PDR.html`）、決定のページの置き場所（`ADR/` と `PDR/`）、題に付けるアイコンだけ。

- `ADR.html` と `PDR.html` に、`group` ごとに h2 を置き、決定のつながりを、過去から未来へ左から右に箱と矢印で並べる。打ち消された決定の箱は、破線で薄く出す
- 箱の幅はそろえ、題は箱の中で折り返す。つながりは 1 列に並べ、並びきらないときは、その列を横にスクロールする
- つながりのない決定は、1 列に 1 つずつ並べず、まとまりのつながりの後ろに、箱を折り返して並べる。決定が増えても、ページが縦に伸びすぎないため
- 箱は決定のカードで、クリックすると決定 1 つのページ（`ADR/<group>/<title>.html` か `PDR/<group>/<title>.html`）を開く。決定 1 つを 1 ページにする
- 決定のページには、題を h1 にし、本文を出す。本文の見出しは h2 から始まるように段を付け直す。id と日付は出さない
- 打ち消された決定のページには、h1 の下に、打ち消されたことと、打ち消した新しい決定へのリンクを出す。下のカードまで読まなくても分かるように
- 決定のページの下に、前後の決定をカードで出す。打ち消した過去の決定は「← 過去の決定」の見出しを付けて左に、この決定を打ち消した新しい決定は「新しい決定 →」の見出しを付けて右に置く。新しい決定へのつながりは、生成するときに `supersedes` を逆にたどって組み立てる
- カーソルキーの ← と → で、前後の決定のページに移れる。前後に決定が複数あるときは、先頭のカードのページに移る。移れることは、カードの下に書く

```
言語
+-----------+   +-------------+
| Go にする | → | Rust にする |
+-----------+   +-------------+
+--------------+  +---------------+
| React にする |  | Python も使う |
+--------------+  +---------------+
```

## 5. 現在の設定のページ

`docv build` は、HTML の「現在の設定」のページに、`docv.yaml` のすべての項目と今の値を 1 つの表で並べる。何を設定でき、どれが効いているかを、スキーマを読まずに見るためのページ。

- ページの名前の h1 の下に、項目の表を「docv.yaml」の h2 で置く
- 項目は、`dir.output` のように、キーを `.` でつないだ名前で出す。並びは、スキーマの順
- 書いていない項目は、既定の値で出す。値のない項目は `-` を出す
- 配列の項目は、要素を箇条書きにする
- 選ぶ項目（true か false、allow か deny など）は、候補を横に並べ、選んでいる候補に色を付ける
- 表の後に、textlint の検査項目と非検査項目（[設定ファイル](config.md) のページの「textlint」の章）を、それぞれ表で並べる
- Slot ファイルや Free ファイルから `docv.yaml` へのリンクは、HTML ではこのページに向ける

---

## 6. レビューガイドのページ

`docv build` は、HTML のレビューガイドのページ（サイドバーの Review Guide）に、`docv review-guide` と同じレビューの手順を出す。レビューするときに AI Agent が読むものを、人間も普段から同じ観点で読めるようにするため。サイドバーにあれば、レビューのコマンドがあることも忘れにくい。

- 手順は、`docv review-guide` と同じファイルから作る
  - 人間と AI Agent が読むものをずらさないため
- 一覧は出さず、一覧の見出しの下に、`docv review-guide` を実行したときに作ることを書く
  - build した時点の一覧になり、ずれるため
  - HTML を git で管理していると、Slot や ADR を足すたびに差分が出るため
- 手順の h1 は除き、ページの h1 を Review Guide にする
  - h1 の下に、`docv review-guide` が出す手順と同じ内容であることを書く
  - 手順の見出しは、h2 から始まるように段を付け直す
- 検索の索引に入れない
  - プロジェクトのドキュメントではないため

---

## 7. 毎回同じ出力にする決まり

- 生成日時、実行したマシンのパス、乱数を出力に入れない
- 並び順を固定する。Slot は規格の順（ページに分けた Slot のページは `order` とパスの順）、Free ファイルはディレクトリのツリーの順、Slot の中の項目は書いた順にする。ADR と PDR は日付と id の順。検索の索引は、Slot ファイル、ADR、PDR、Free ファイルの順
- 入力（管理対象のファイル、`README.md`、Slot、ADR、PDR、`docv.yaml`、docv の版）が同じなら、HTML、`docv.css`、`docv.js`、インデックスはバイト単位で同じになる

## 8. インデックス

build は、毎回 `document_root` の直下に `README.md` を書く。GitHub でリポジトリを開いた人が、clone しなくても Slot ファイルを読めるようにするためのリンク集。名前を `README.md` にするのは、GitHub で `document_root` を開くと、一覧の下に表示されるため。ルートの README からリンクして使う。

- Slot を、HTML の Slot のページ（`index.html`）と同じく、まとまりごとに規格の順で、リンクの箇条書きにして並べる。ページに分けた Slot は、Slot の名前の下に、ページを `order` の順に入れ子で並べる。置いていない Slot は出さない
- Slot は、元のファイルへリンクする。GitHub で Markdown のまま読めるため。ファイルがシンボリックリンクなら、ルートの中にある先のファイルへリンクする。GitHub は、シンボリックリンクを開いても先の中身を出さないため
- Free ファイル、ADR、PDR は、それぞれの章に、置いているディレクトリへのリンクだけを出す。どれも詳細やプロジェクト固有の情報で、知りたくなった人は clone すると考えるため。検索とタグでの絞り込みは Free のページで、ADR と PDR のつながりの図はそれぞれのページで見られると、`docv open` と、そのページのルートからのパスで案内する
- リンクは、`README.md` の場所からの相対パスで、`[名前](<パス>)` の形で書く。パスに空白や日本語が入っても、GitHub で辿れるようにするため
- 1 行目に、docv が作ったことを示すコメントを書く。build は、このコメントで始まらない `README.md` を書き換えない（[コマンド](cli.md) のページの「ファイルを書くコマンド」の章）
- 末尾に、作った docv の版を `Generated by docv <版>` の形で書く。GitHub で見ても、docv が作ったファイルであり、手で直すものではないと分かるようにするため
  - docv と版は、サイドバーと同じく、リポジトリとその版のタグのソースへリンクする
- インデックスが古いままかは、check で確かめない。Slot を変えたら build で作り直す
- エイリアス（シンボリックリンク）やコピーを並べたディレクトリは作らない。GitHub はシンボリックリンクの先を出さず、コピーは同じ中身を 2 か所で持つことになり、md の中の相対リンクも壊れるため
- HTML にも、インデックスと同じ並びの Index のページを作る。リンクは、md ではなく、HTML のページに向ける。Free ファイル、ADR、PDR は、それぞれの一覧のページへリンクする。末尾には、インデックスと同じく作った docv の版を出す

---

## 9. diff-open の HTML

`docv diff-open` は、build と同じ作りの HTML に、`--from` のリビジョンから変わったファイルの印を付けて作る。インデックスは作らない。

ファイルごとに、新規、変更、削除のどれかの印を付ける。新規は `--from` になく今あるファイル、削除は `--from` にあり今ないファイル。

| 場所                                          | 新規     | 削除                 | 変更 |
| --------------------------------------------- | -------- | -------------------- | ---- |
| Slot のカード、ADR と PDR の箱                | 緑の枠   | 赤の枠               | 鉛筆 |
| ページに分けた Slot のタブ、Free のページの行 | 緑の背景 | 赤の背景と取り消し線 | 鉛筆 |
| サイドバーの項目                              | 鉛筆     | 鉛筆                 | 鉛筆 |

- 新規と変更と削除で、見た目を分ける。見た人のすることが違うため
  - 新規はページを全部読み、変更は差分を読み、削除は消してよいかを確かめる
- 鉛筆を付けた要素にマウスを乗せると、鉛筆の右に、足した行数と消した行数を出す
  - サイドバーの項目では、新規、変更、削除のファイルの数を出す
  - サイドバーの README と Config は、ファイルが 1 つなので、ファイルの数の代わりに行数を出す。2 つにはカードがなく、ほかに行数を見る場所がないため
- ページに分けた Slot のカードは、すべてのページが新規なら緑の枠、すべてのページが削除なら赤の枠、ほかは鉛筆にする。行数は、変わったページの合計
  - 今あるページに 1 つ足しただけの Slot を、新規にしないため
- 消したファイルも、カード、箱、タブ、行として出し、消したファイルのページへリンクする
  - 消したファイルのページは、作業ツリーから消えたことと、`git diff` のコマンドだけを出す。中身は出さない
  - 消した Slot は、未作成のカードに赤の枠を付ける
  - 消したページのタブは、ファイルの名前で出す
- 変わったファイルのページでは、h1 の上の元のファイルのパスの代わりに、`git diff <rev> -- <path>` のコマンドを出し、ボタンでコピーできるようにする。ページの中には差分を出さない
  - コマンドは、docv ルートで実行するものにする
  - 英数字、`/ . _ -`、ASCII でない文字のほかを含む引数は、単一引用符で囲む。シェルへそのまま貼れるようにするため
  - まだ git に追加していないファイルは、`git diff` に出ないので、パスのまま出す
  - README と Config のページは、build ではパスの行を出さないが、diff-open では変わったときだけコマンドの行を出す
- サイドバーのプロジェクトの名前の下に、どのリビジョンと比べたかを出す
- 画像の変更には、印を付けない
