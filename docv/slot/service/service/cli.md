# コマンド

どのコマンドにも共通する決まり。コマンドごとの使い方は、[利用マニュアル](../manual.md)。

---

## 1. ルートと出力

- docv ルートで実行するコマンド（利用マニュアルのコマンド一覧）は、カレントディレクトリをルートにし、そこにある `docv.yaml` を読む。親のディレクトリは探さない
- 結果は標準出力に、エラーは標準エラーに出す

---

## 2. ファイルを書くコマンド

| コマンド | 書くもの                                                                                                                                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| init     | `docv.yaml` だけ。`--print` のときは書かない                                                                                                                                                                                  |
| slot gen | 指定した Slot ファイルだけ。`--print` のときは書かない                                                                                                                                                                        |
| fix      | 管理対象のファイル、md の Slot、ADR、PDR、YAML の Slot だけ。整形と textlint の自動修正だけをする。YAML の Slot は、Markdown の項目の中身だけを直す。`docv.yaml` と YAML の Slot は、末尾の改行も整える                       |
| build    | `dir.output` の下の `html/` と `image/` の中と、`document_root` の直下の `README.md` だけ。出力先は、目印の `.docv` を残して中を消し、作り直す。`generate.image` が false のときと、`--no-image` のときは `image/` に触れない |

- ほかのコマンドは、ファイルを書かない
- `CLAUDE.md`、リポジトリのルートの `.gitignore`、hook の設定は、どのコマンドも書かない
- build は、出力先に `.docv`（docv が作った目印）がなく、空でもないときは、何も書かずにエラーで終わる。`dir.output` を間違えて既存のディレクトリを指しても消さないため
- build は、すでにある `document_root` の `README.md` の 1 行目に docv の印のコメントがないときも、何も書かずにエラーで終わる。手で書いた同じ名前のファイルを消さないため

---

## 3. 終了コード

| コード | 意味                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| 0      | 成功。check で指摘が 1 件もない                                                              |
| 1      | check で指摘（error）が 1 件以上ある。fix で直せないファイルがある。open に対応していない OS |
| 2      | `docv.yaml` がスキーマに合わない、引数が正しくない、など実行できない                         |

## 4. 言語

CLI のメッセージ、ヘルプ、docv の概要、テンプレは、日本語だけで書く。切り替えはできない。英語に訳した版を持つと、同じことを 2 か所で揃え続けることになるため。
