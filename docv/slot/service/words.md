# 用語集

## ファイルの種類

| 用語 | 英語 | 意味                                                                                                                                                                                                                                 |
| ---- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Slot |      | どのプロジェクトにも要るドキュメントを書くファイル（Slot ファイル）。docv がミッションと形を決める。`docv.yaml` の `dir.document_root` の下の `slot/`（既定は `docv/slot/`）に、`<まとまり>/<ID>.md` の名前で置く。21 の Slot がある |
| Free |      | プロジェクトがミッションと形を決める Markdown のファイル（Free ファイル）。AI Agent が読み書きし、詳細を記録する。`dir.document_root` の下の `free/`（既定は `docv/free/`）に置く                                                    |
| ADR  |      | Architecture Decision Record。技術の決定 1 つを、背景、選ばなかった案と一緒に残す記録。`docv/adr/` に 1 つの Markdown で置き、決めた後は書き換えない                                                                                 |
| PDR  |      | Product Decision Record。プロダクトやサービスの仕様の変更 1 つを、その理由、見直す条件と一緒に残す記録。`docv/pdr/` に 1 つの Markdown で置き、決めた後は書き換えない                                                                |

## 決まりの種類

| 用語         | 英語      | 意味                                                                                                                                                                     |
| ------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ルール       | Rule      | docv の仕組みが決める決まり。Slot の名前とミッション、`docv.yaml` のスキーマ、YAML front matter の key、check が確かめることなど。利用側は変えられず、`docv desc` で見る |
| ガイドライン | Guideline | 利用側がドキュメントを書くときの方針。調整の余地があり、利用側が自由に直す。Slot の Doc ガイドに書き、`docv gen doc-guide` で雛形を作る                                  |
| 設定         | Config    | `docv.yaml` で切り替えること。check のルールや textlint を使うか、出力を git で管理するかなど。`docv init --print` で見る                                                |

## ファイルの分類

| 用語     | 英語 | 意味                                                                                                          |
| -------- | ---- | ------------------------------------------------------------------------------------------------------------- |
| 管理対象 |      | `dir.document_root` の下の `free/` にある Markdown。YAML front matter に `mission` が要り、check の対象になる |
| 管理外   |      | `dir.document_root` と `dir.output` の外にある Markdown。docv は中身を見ない                                  |

## 書き方

| 用語       | 英語    | 意味                                                                                                                                                                                  |
| ---------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ミッション | Mission | そのファイルを読むと何が分かるか。Slot のミッションは docv が決め、Free ファイルのミッションは YAML front matter の `mission` に 1 文で書く。中身は、ミッションに収まることだけにする |
| タグ       | Tags    | Free ファイルに付ける分類。1 つのファイルに任意の数を付けられ、タグにルールを付けられる                                                                                               |
