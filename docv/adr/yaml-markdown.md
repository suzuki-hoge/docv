# YAML の Slot の Markdown は、_markdown で終わる項目に | で書き、検査する

## 背景

YAML の Slot には、Markdown として HTML に出す項目（`desc`、`purpose`、`markdown` など）と、ただの文字の項目が混ざり、名前では見分けられなかった。Markdown の項目は、リンク切れ、書式の規則、textlint のどれでも確かめていなかった。値の書き方（1 行、クォート、`|`、`>`）がまちまちで、指摘の行番号を YAML の行に戻せず、fix で書き戻すこともできなかった。

## 決めたこと

- Markdown の項目は、名前を `_markdown` で終わる形にする。`desc_markdown`、`purpose_markdown`、`body_markdown`、`local_from_markdown`、`release_from_markdown` の 5 つ。ディレクトリの `description` も `desc_markdown` にする
- Markdown の項目の値は、1 行でも必ず `|` のブロックで書く。`|-` や `|+` などは使わない。それ以外の文字列の項目は 1 行で書く。どちらも check が確かめる
- Markdown の項目の中身に、リンク、書式の規則、整形、textlint をかける。見出しの検査はかけない。指摘の行番号は YAML の行番号で出し、fix は中身を直して字下げを付け直す
- 中身の多くは表のセルに出す短い説明なので、textlint の `ja-no-mixed-period`（文末の「。」）はかけない

## 結果

名前で Markdown かどうかが分かり、どの Markdown も同じ基準で確かめる。短い値も `|` で 2 行になり、YAML は長くなる。行番号の分かる YAML のパーサー（yaml-rust2）を依存に足す。

## 選ばなかった案

| 案                                      | 選ばなかった理由                                                       |
| --------------------------------------- | ---------------------------------------------------------------------- |
| 1 行の値は `\|` なしも許す              | 行番号の戻し方と fix の書き戻し方が、値の書き方の数だけ要る            |
| Markdown の項目の一覧を Slot ごとに持つ | 名前で見分けられれば、書く人にも分かり、検査も Slot ごとに分けずに済む |
| 短い説明にも「。」を求める              | 表のセルに出す説明の書き方が、Free ファイルの表と揃わない              |
