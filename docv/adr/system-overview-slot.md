# システム概要の Slot を足し、システム仕様と分ける

## 背景

システムのまとまりには、システム仕様、技術スタック、API 仕様書、DB 仕様書があり、システムをざっと理解するための Slot がなかった。システム仕様のミッションは「部品の構成と役割、部品の間の流れと、部品をまたいで守る決まり」で、全体を見せることと、詳しい決まりを書くことの 2 つが入っていた。詳しく書くほど、全体をつかみたいだけの開発者が、システム仕様の中から全体像を探すことになる。サービス仕様では、同じ理由でサービス概要を分けている。

## 決めたこと

システム概要の Slot（`system/system-overview.md`、md）を足す。ミッションは「開発者に向けた、システムを作る部品と、そのつながりの全体像」とする。システム仕様のミッションは「部品ごとの振る舞いと、部品の間の流れと、部品をまたいで守る決まり」にする。サービス仕様のミッションは変えない。

システムのまとまりは、システム概要、システム仕様、技術スタック、API 仕様書、DB 仕様書の順に並べる。

Doc ガイドの雛形の言葉の使い分けでは、アーキテクチャの全体像を、システム概要に SVG の図で書くことにする。サービス概要に書く「サービス説明」の言葉も足す。

## 結果

開発者は、システム概要の図だけで、どんな部品があり、どうつながっているかが分かる。システム概要は部品の役割とつながりを、技術スタックはそれを作る技術を書き、同じことを 2 か所に書かない。システム仕様の `mission` は変わるので、すでにある md の Slot は check の error で直す。

## 選ばなかった案

| 案                                               | 選ばなかった理由                                                      |
| ------------------------------------------------ | --------------------------------------------------------------------- |
| システム仕様の冒頭に全体像を書く決まりにする     | md の Slot の中身の形は決めないので、全体像を書いたかを確かめられない |
| 技術スタックに、部品のつながりを書ける項目を足す | 技術の一覧と、部品の構成図は、読む目的が違う                          |
| Slot の ID を `architecture` にする              | Slot の名前（システム概要）と ID の対応が読み取れない                 |
