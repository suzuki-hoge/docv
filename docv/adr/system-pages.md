# システム仕様も、サービス仕様と同じくページに分けられるようにする

## 背景

ページに分けられるのは、サービス仕様だけだった。システム仕様も、画面、サーバ、バッチのように部品が多いシステムでは、部品ごとの振る舞いが 1 つのページに並んで長くなる。部品を 1 つだけ知りたい開発者が、長いページの中から探すことになる。

## 決めたこと

サービス仕様とシステム仕様は、1 つのファイルの代わりに、1 ページ 1 つの Markdown で置けるようにする。置き場所は、`service/service.md` の代わりに `service/service/` の直下、`system/system.md` の代わりに `system/system/` の直下とする。どのページにも、YAML front matter に `order` と、その Slot の `mission` を書く。ページの並びは `order` で決め、本文の h1 をページの名前にする。HTML では、ページを 1 つずつ `<まとまり>/<Slot>/<h1>.html` にし、Slot の名前の下に、ページへのリンクをタブにして並べる。

分けないときは、今までどおり 1 つのファイルに書く。分けられるのは、サービス仕様とシステム仕様だけにする。

どこで分けるかは docv では決めない。Doc ガイドの雛形に、分ける目安を書く。読み手、読むタイミング、部品や機能の違う情報が、1 つのページに混ざったら分ける。

## 結果

システム仕様も、部品ごとにページを分けて読める。分け方、検査、HTML の作りは、サービス仕様と同じになる。`docv desc` の案内は、「ページ分け」の章にまとめる。AI Agent は、`docv desc` で分けられることを、Doc ガイドで分ける目安を知る。

## 選ばなかった案

| 案                                             | 選ばなかった理由                                                |
| ---------------------------------------------- | --------------------------------------------------------------- |
| どの md の Slot も、ページに分けられる         | 利用マニュアルや API 仕様書を分けるかは、まだ要るかが分からない |
| システム仕様だけ、部品ごとの決まった形で分ける | md の Slot の中身の形は決めない。分け方はプロジェクトごとに違う |
