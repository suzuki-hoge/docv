# サービス仕様をページに分けられるようにする

## 背景

サービス仕様は 1 つの md の Slot で、HTML でも 1 つのページになる。利用者向けの機能と管理者向けの機能のように、読む人ごとに仕様が分かれるサービスでは、1 つのページが長くなり、読む人が自分に関わる部分を探すことになる。

## 決めたこと

サービス仕様は、`service/service.md` の代わりに、`service/service/` の直下に 1 ページ 1 つの Markdown で置けるようにする。ページの並びは YAML front matter の `order` で決め、本文の h1 をページの名前にする。HTML では、ページを 1 つずつ `サービス仕様/サービス仕様/<h1>.html` にし、Slot の名前の下に、ページへのリンクをタブにして並べる。

分けないときは、今と同じく `service/service.md` に書き、YAML front matter はいらない。分けられるのは、サービス仕様だけにする。

## 結果

すでにある `service/service.md` は、そのまま 1 ページのサービス仕様として読める。分けたページにも、ほかの md の Slot と同じ検査をかける。目次、検索、ほかのファイルからのリンクは、ページごとに効く。

## 選ばなかった案

| 案                                                   | 選ばなかった理由                                                                           |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `docv/service-specs/` のように、`docv/` の直下に置く | Slot をまとまりのディレクトリの下に置く決まりが崩れる                                      |
| 分けないときも、ディレクトリに置く                   | すでにある `service/service.md` を移すことになる                                           |
| ページの名前を YAML front matter に書く              | 本文の h1 と同じ名前を 2 か所に書くことになる                                              |
| 1 つの HTML の中で、CSS でタブを切り替える           | 目次に全ページの見出しが混ざる。検索の結果や見出しへのリンクから、隠れているタブを開けない |
