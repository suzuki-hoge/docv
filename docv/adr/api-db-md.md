# API 仕様書と DB 仕様書を md だけにする

## 背景

API 仕様書と DB 仕様書は、yaml（外の定義への `ref` だけ）と md のどちらでも置けた。Slot の名前は `api-yaml` と `api-md` のように形で分かれ、yaml のときだけページを作らず、カードから定義へ直接リンクしていた。形が 2 つあるため、名前、check、HTML のリンクに、この 2 つの Slot だけの決まりが要った。

## 決めたこと

API 仕様書と DB 仕様書は md だけにし、Slot の名前を `api` と `db` にする。ほかの md の Slot と同じく、ページにしてそのまま出す。

## 結果

すべての Slot が、形を 1 つだけ持つ。同じ Slot のファイルが 2 つになることがないので、slot-duplicate はなくなる。外の道具で作った定義は、md の中に書き添える。

## 選ばなかった案

| 案                      | 選ばなかった理由                                      |
| ----------------------- | ----------------------------------------------------- |
| yaml と md の両方を残す | 名前、check、リンクに、2 つの Slot だけの決まりが残る |
| yaml（`ref`）だけにする | 説明を書く場所がない                                  |
