# docv のルール

このリポジトリのドキュメントは docv で管理している。ドキュメントを読む・書く・直すときは、このルールに従う。ファイルの一覧と、それぞれが答える問いは `docv index` で見る。

---

## 1. 考え方

- ドキュメントを時間で分ける。未来（これからやること、検討中のこと、決まっていないこと）、現在（今の状態）、過去（外した内容と理由）
- 現在のドキュメントには、最新の状態だけを書く。状態が変わったら、前の内容を直接書き換える
- やったことはドキュメントに書かず、PR とコミットメッセージに書く
- 仕様は、実装されているかどうかにかかわらず「こうあるもの」として書く。実装状態は書かない
- ファイルごとに、答える問いを frontmatter の question に 1 文で書く。中身はその問いへの答えだけにする
- docv.yaml の docs に当てはまるファイルだけが管理対象。それ以外は管理外で、自由に書いてよい

---

## 2. 種類

| 種類 | 時間 | 答える問い | 書くこと |
|---|---|---|---|
| overview | 現在 | これは何で、どこから見ればいいか | 目的、構成、入口。プロジェクトに 1 つ |
| spec | 現在 | 〜はどう振る舞うか、どうあるべきか | 振る舞い、データの意味、境界、今の状態の理由（1〜2 行）。コードを読めば分かることは書かない |
| operation | 現在 | どう実行するか | コマンド、手順、うまくいかないときの対処。1 つの章に 1 つの作業 |
| cost | 現在 | 何にいくらかかるか | 単価（いつ時点か）、見積もり、費用を理由に決めていること。「単価」「見積もり」を含む章が要る |
| rule | 現在 | どう書くか、何を守るか | 書き方や守ること。人間が書き、AI Agent は読むだけ |
| plan | 未来 | 何をやるか | やると決めたタスクを `- [ ]` で書く。frontmatter の status に todo / doing を書く |
| proposal | 未来 | 何をどう変えることを検討しているか | 背景、案、決めること。「案」「決めること」を含む章が要る |
| fixme | 未来 | 何が決まっていないか、何を調べるか | 1 つの章に 1 つの項目。見出しは問いの形 |
| archive | 過去 | 何を外し、なぜ外したか | `docv retire` が書く。手で書かない |
| tmp | なし | 後で見るかもしれないものは何か | まとまっていない意思決定やメモ。ルールはない |

docv.yaml の kinds で、プロジェクト独自の種類が足されていることがある。時間が同じ組み込みの種類と同じように扱う。

---

## 3. 書く前に決めること

1. 書くべき変更か。仕様、手順、費用、規約、計画、検討、未決のどれかが変わったときだけ書く。コードを変えただけなら書かない
2. どの種類か（2 章）
3. どのファイルか。`docv index` で各ファイルの問いを見て、問いに収まるファイルを選ぶ。収まるファイルがなければ `docv new` で作る

---

## 4. 何をどこに書くか

| 書く内容 | 書く場所 |
|---|---|
| やったこと | PR とコミットメッセージ。ドキュメントには書かない |
| 決まったこと | 現在のドキュメント。前の内容を直接書き換える |
| 今の状態の理由 | 現在のドキュメントに 1〜2 行 |
| 捨てた案、前の状態、議論の経緯 | archive。`docv retire` で移す |
| 検討中の変更 | proposal |
| 決まっていないこと | fixme |
| 実装状態、コードの改善点 | 書かない。必要なら Issue にする |
| まとまっていない意思決定、後で見るかもしれないメモ | tmp |

- 現在のドキュメントに `〜に変更した`、`以前は`、`未実装` のような言い回しを書かない
- 古い内容は、残す価値があるとき（なぜ変えたか、何と比べて捨てたか）だけ `docv retire` で archive に移す。それ以外は消す
- plan の終わったタスクは消す。チェックを付けて残さない。すべて終わったらファイルごと消す
- proposal は、採用したら現在のドキュメントを書き換えてから、却下したらそのまま、理由を付けて `docv retire` する
- fixme は、決まったら答えを現在のドキュメントに書き、項目を消す
- tmp のファイルには、ほかのドキュメントからリンクも言及もしない。いつ消えてもよいため

---

## 5. 範囲を守る

- 問いに収まらない内容を足さない
- 内容を収めるために、問いを広げない
- 問いに対してファイルが大きくなったら、問いを分け、ファイルも分ける

---

## 6. frontmatter

```yaml
---
question: 注文の処理は、どの注文をいつ確定し、失敗したときにどう扱うか
topics: [注文]
---
```

| key | 対象 | 中身 |
|---|---|---|
| question | すべての種類（tmp を除く） | このファイルが答える問い。1 文の、疑問の形で書く。docv.yaml で与えられていれば書かない |
| topics | すべての種類 | docv.yaml の topics にある話題だけ |
| status | plan | todo / doing |
| source | archive | 移した元のファイルのパス |

章番号、文体、強調の使い方などの書式は、プロジェクトの rule に従う。

---

## 7. 読むもの

- 現在と未来のドキュメントは、必要なものを読む
- archive は、経緯を聞かれたときだけ読む
- docv build の出力（HTML）は読まない、書かない

---

## 8. コマンド

```sh
docv index                    # 管理対象のファイルの一覧と問いを出す。セッションの最初に実行する
docv index --all              # archive のファイルも並べる
docv new docs/spec/order.md   # その場所の種類のテンプレでファイルを作る
docv check                    # ルールに沿っているかを確かめる。ドキュメントを変えたら実行する
docv check docs/spec/order.md # 指定したファイルだけ確かめる
docv fix docs/spec/order.md   # 整形と textlint の自動修正をする
docv retire docs/spec/order.md --section "注文履歴" --reason "履歴は監査ログにまとめた"
docv retire docs/proposal/coupon.md --reason "却下。決済サービスの手数料に見合わない"
```

- `docv check` の error は直す。warn も、言い回しの警告なら書き換えるか retire する
- `docv retire` の `--section` には、章の見出し（章番号を除く）か章番号を渡す。省略するとファイル全体を移す。`--reason` は必須
- `docv retire` のあとに出るファイルの、移した元へのリンクを直す
